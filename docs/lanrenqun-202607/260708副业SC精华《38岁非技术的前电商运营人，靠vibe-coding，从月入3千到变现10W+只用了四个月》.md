# 二、网站运营

## 1、定位

做网站的定位，要先问自己，我有什么？

我有：

- ①匹配大多数主流行业的电商出图工作流（优点是通用性强，不足的地方是缺乏垂直行业的深度定制优化）。
- ②可合作的博主与电商人脉（中小卖家居多，各行各业都有）。

垂直行业的电商出图网站当然是更好的选择，可以小而美，做精做深。但我的需求是快速变现，如果自己去做垂直行业的账号，肯定不满足我的需求。和现有技术源码与渠道资源匹配的，只有做针对中小卖家的通用型电商生图网站。

## 2、定价策略

定价策略我从三方面决定：一、同行；二、客户群体；三、自身资源和条件。

同行：电商生图在我的认知里没有绝对头部，相对头部是美图设计室这类平台。它的定价不到一块钱一张。也有2—3毛钱左右一张图的卖家，核心竞争力就是极致的性价比。还有主打高端跨境电商、一张图五块钱以上的。

客户群体：如果是大卖家，他们选择做图工具的核心决策点主要有两个：要么出图效果深度定制化，要么价格极致地低。对中小卖家来说，需求就没那么极端，生成的结果可以商用，有成交转化，操作简单快捷，价格明显比请美工低，就能符合需求。

自身条件：深度定制化虽然能卖高客单，但在业务优化上投入精力和资源会很大，明显不适合我。极致低价，价格比市场主流价格低80%，我需要二十倍以上的获客才有普通定价下同样流量的收益。过低的定价，给到分销合作者的比例就不多，严重影响积极性，且20倍的获客量很不现实。再者，20倍的用户量，会大大增加我的服务器成本、技术成本、精力投入等，明显不适合我。最终我选择了略高于美图的1元左右定价。

充值套餐金额从49到499。这几个月统计下来，平均客单价在100元以上。

## 3、从 demo 到 MVP

网站功能可用，哪怕用户已经充值了，也只是 demo。从 demo 到 MVP，需要跨过一条线。我这里称之为业务死线，它就是木桶的底板。底板漏水，无论木桶的边长边短都没有意义，存不住水，留不下一个用户。

在电商生图这个领域，业务死线就是大模型不能改变产品的原外观，否则再精美也是废稿。

Nano Banana Pro 和 GPT 这种最前沿的生图大模型，比传统的 ComfyUI 更智能，不需要复杂的提示词就能出惊艳的效果，缺点也很明显，它常常会对产品做二创。

网站上线测试后，第一批测试用户反馈了这个问题。如果换成 ComfyUI，提示词难度和画面自然度都要大打折扣。我的改进方案是给每张图加入限制提示词，经过两三天的测试，平衡了大模型乱改原图与画面灵活性，某种程度上解决了这个问题。所以网站才有每个月将近30%的老客占比。

## 4、推广渠道

作为我第一个AI coding的项目，推广我没有亲自上阵。如果整个项目闭环都是自己不熟悉的环节，很难短时间内把闭环打通，我选择了借力。

联系了以前大部分的电商人脉资源，有电商博主、刷单主持、电商公司的老板，甚至想找兼职的素人。

最后跑出来、出业绩大头的是电商博主，这里就只讲电商博主的合作推广方式。和我合作的两个电商博主，都有两个共同点：一是我半年内付费买过他们的课程服务（不多，300—500元）；二是我还给他们开发过电商小工具，并在小工具上加上他们专属的微信二维码广告，方便他们的学员帮他们分享裂变。

电商博主有四大优势：人群精准、有粉丝基数、懂目标用户的需求、会做内容。而且电商培训市场冷清，电商博主都在主动寻找其他变现方式。

我把网站的功能演示和生成案例交给他们，基本上不用我操心后面的事，第一个月就顺利出了八千多的业绩。

为了提升信任度，我给每个上了分销权限的合作者后台公布了实时业绩数据。附图是我小号的分销后台。

## 5、渠道分润

做项目，流量为王。我的分销渠道策略是把合作者当合伙人，而不是外包或外部推广。提成比例高达42%，并且为了提高合作者的积极性和参与度，用户复购和用户裂变，都统计到合作者的业绩里，只要推一波流量，一两个月内就会有不错的收益。

也为了后续的放大，我还设计了二级分销，只不过素人如果没有人带，很难坚持下去。这部分分销人群，也是我后面要扩展的地方。

## 6、内容形式

获客的短视频内容形式我们主要有三类：

- 1、口播介绍产品+案例展示。
- 2、不出镜演示效果。
- 3、针对用户场景做干货分享类。

我们发的第一条视频就是口播介绍，产出成本比较低，效果中等。适合电商博主，只要把功能和卖点说一下，生图的图片作一个展示即可。

不出镜演示效果，也有穿插使用，属于投产比很高的内容形式，素人也可以做。制作简单，周期短，也有引流私域的效果。后续如果要放大，我应该会采取这种形式。如果自己有团队的圈友，可以参考这种形式。

针对用户场景做干货分享类的视频，制作难度较高，但是效果最好。业绩最好的几十万粉博主就是以这种形式为主，一个月只制作两条这样的视频。

朋友圈的促转化也是必要的动作。

## 7、私域维护

我在网站加上了微信二维码，用定期积分抽奖作为钩子，网站有将近20%的用户会沉淀到私域里。群里每周或每次重大更新，我就放出三百张图的额度给群里的客户抽奖，中奖的人有三张图的额度，但不足以生成全套图片，相当于促进了用户充值。

加到私域还有几个好处：一是更方便了解用户需求；二是定期的抽奖和更新公告提升用户的信任度；三是指导用户更好地生成图片。

## 8、客户运营与敏捷开发

通过私域沟通，实际测下来，网站的客户以中小卖家为主。一开始我以为服饰鞋包会是大头，实际运营中，我发现用户不少是各种日用品、工业品、小电器的卖家。

最近几个月，平均每月将近300个客户充值，目前多次复购的订单占30%左右。前期还吸引了少数跨境卖家，根据卖家的需求，我增加了十多国语言的支持，但由于图片清晰度不达4K，大部分跨境卖家流失了。

用户的需求痛点有很多，我并不能一一满足，不过几个主要的痛点，我还是做了相应的功能满足用户的需求。除了前面提到的大模型二创产品的业务死线，不少用户要求对文案和画面、构图有个性化的需求。

我针对性地开发了自由生图页面，让用户自行输入提示词，DIY自己的商品营销图。（这个功能页面甚至用不上复杂的工作流，直接把生图大模型的API对接到页面上就能实现。）

更多的用户是看到同行做得好的图片，想要模仿。我对应开发了图片克隆功能，用户只需上传自己的产品图片和竞品的主图或详情，即可一键克隆产品图。

根据客户提出的建议和需求，最开始两个月，我平均一天更新三次。到现在已经有十多个业务功能页面，还增加了十多个免费小工具。

# 三、项目开发（1.0版本）

网站的设计文档，我基本用 Codex 来完成。代码的落地用了 VS Code + Kilo 插件 + GLM-5.0模型。

## 1、核心功能逻辑

网站最开始唯一的核心功能：一键生成电商主图、详情图。用户上传参考图，输入产品名称和产品介绍，自动生成电商营销图片。

（这个功能现在 GPT 也能实现。2月份网站上线时，市面上商用级生图模型只有 Nano Banana Pro，当时并不能一键出全套商品图。）

这个核心功能不是我的原创，而是我从网上看到一个 n8n 工作流模板，拆解了它的流程和提示词。

## 2、系统功能

系统功能主要包含了邮箱验证系统、充值系统、积分系统、用户裂变系统、分销统计页面。

## 3、网站层次

网站层次不要太复杂，我用了“页面 > 模块 > 功能”三级层次。大模型的注意力和推理能力有限，层次过多，会严重影响开发效率，甚至出现难以修复的 Bug。

## 4、开发流程

商用网站功能多、逻辑链条较长，大模型的记忆力和注意力非常有限，不能想到哪就让它做哪。我第一步是让它根据核心功能和系统功能做出设计文档。

### ①设计文档

包含了前端页面、网站所有功能、技术栈、后端等。明确了前面的核心功能和系统功能，以及你的服务器配置和用户规模的预期，AI就能生成完整的设计文档。我们只需要审核文档，对不符合预期的地方提出修改意见。

### ②代码搭建

严格按照设计文档落地搭建，一般半天左右就能完成。这一步是搭建网站的脚手架，不要纠结功能有没有跑通。

### ③完善功能

建好项目脚手架，先审核代码，修复代码语法问题、逻辑问题等。修复完成后，如果功能有更新，让大模型同步到设计文档.md和 README.md 当中。每次更新先引用相关文档，让大模型读一遍文档。

目前大模型的前端测试还比较弱，AI自主检测和修复完可检测的代码 Bug 后，最后一步是人工模拟用户行为，对整体功能进行测试。

### ④重构前端

设计这个网站，我没有使用专门的前端 skill，首次生成的页面效果不是很满意。

用国外的UI设计网站会员的话，价格有点高。我选了较省成本的折中办法，开通了百度9.9元的秒哒会员，让它生成了新的前端代码。再把代码交给 GLM，将新的前端设计更新到网站上。

### ⑤部署网站

本项目开发完雏形，就让大模型提供部署文档，按步骤部署到服务器上。（新的项目我直接用 ZCode 在服务器上开发、部署和更新，效率要高好几倍。）

### ⑥更新迭代

网站的更新主要集中在前三个月，平均每天更新3个版本，coding时间大概有80%在修 Bug。大多数的 Bug 通过观察错误现象和代码更改前后的变化，汇总给AI，一到三轮迭代就能解决。少数需要多轮对话。

目前只遇到过一次长时间无法修复的 Bug：A页面的一键下载功能，用户点击就能下载；B页面的下载功能，用户点击下载直接失败。

我原本就没有用代码开发的经验，AI用的编程语言我听都没听过，只是大概知道这个 Bug 是因为图片鉴权问题，导致用户浏览器没法一键将页面显示的图片打包，迟迟没修复。折中的方式是在服务器后台打包，需要等待两分钟左右才能下载；或者让用户点开图片单张保存，再者到历史记录中下载。

这个 Bug 直到 GLM-5.2发布，我才在 ZCode 上花了一个多小时解决掉。

我分析核心的原因是代码的逻辑链接条长，同时系统为了图片空间的安全，增加了很多权限设置的限制，导致国产大模型推理能力不够。给我的教训是，业务链条一定要逻辑简单清晰，并且在网站安全与用户体验之间，要做好妥协。

# 四、为什么选这个项目？

大部分圈友都知道选项目应该追风口。风口的好处主要有两个：

- 1、风口领域市场在快速扩张，跟着趋势走很容易做业务增量。
- 2、没有太多专业的同行给你竞争压力，可以轻松发育。

作为超级标的，AI就是最大的风口，但我不会盲目冲进去。AI是跨行业的领域，不是所有AI项目都适合我。

做项目之前，我会先问清楚自己有什么？要什么？

这里我结合自己的经历来解答这个问题。

我当过中移动客服、电商客服，也进过工厂。2014年通过网上报培训班学习SEO，进入网络营销行业。从离开工厂，到成为网络营销公司部门推广负责人，我只用了三个月，并且当月带领营销部门二十多个伙伴实现单月50W业绩，个人业绩6W（前一个月部门总业绩20W出头）。

故事到这里，不出意外就要出意外了。有天上班我看到部门老大在骂一个小伙伴，原因是这个小姑娘做错了一些细节上的问题。她当着所有人的面骂了小姑娘一个多小时，对方一直在哭。那时候我还年轻气盛，忍不住打断了她的“教育”，并且顶撞了她几句，具体说了什么现在记不住了。

第二天我就被调到配套不齐的新部门。连着一个多月，我每隔十天左右就被调到一个新部门，屁股没坐热就被调走，因此患上了焦虑症，干脆辞职回家看医生。最后老板给我批了半年的长假，让我回家休养。

当然，我也没再回到这家公司。后面找的岗位，都是同事介绍的很小规模的公司，资源有限，老板的格局有限。到2023年，我的收入跟2014年的工资基本上处于差不多水平。

这个时候我手里也有些积蓄，年纪也30多了，职场的路没什么盼头，咬咬牙辞职做电商。

刚开店没多久，家里又出了事情。我爸找远房亲戚借了几十万，被骗去投资所谓的地方债务处理项目。项目暴雷，亲戚打我爸电话从来不接，找到我姐的单位去堵人。家里也被堵过很多次，我妈天天怄气。实在没办法，我拿出大部分积蓄帮我爸还了部分债务，事情才消停。

抽空资金，电商创业也做不下去了。短视频时代，过去的网络营销推广方式也相对落后市场，回职场也没什么竞争力。有句话叫穷则变，变则通。没有资金，没有经验优势，也有可行的玩法。我调整了方向，从自己开店改为代运营。

没有成功案例，客户信任度没法建立，我选择了免服务费的策略！靠这个策略很快接手了一家淘宝家具店，花了三个月时间，把一家死掉的老店从月2万销售额（主要是刷单的销售额）做到了33万实际月营销额，五个月做到了实际月营业额67万，广告费只花了三万左右，并且冲到淘宝办公家具类目的TOP200。

管甲方要提成佣金的时候，这位老板以工厂生产不过来、发不出货、退货多为由，将事先谈好的2%营业额提成1.3万多，砍价到三千。多次谈判后约定为3500元，合作了近三年，今年才把店铺运营工作放下。

以上经历，我不责怪任何人，是我的选择决定了我的境遇。

开始 vibe coding 前，我对这些经历做了几条反思：

- 1、建立清晰的边界，尊重他人的命运。被骂的同事、负债的家人，都是他们自己的选择。越过边界干预别人的命运，就是对自己命运的不尊重。对家人、对同事、对客户、对合作伙伴，都应该建立明确的边界，该帮的帮，不该插手的坚决不越界。
- 2、想掌握议价权，要么掌握流量端，要么掌握成交端。假如我想继续深耕代运营，我需要掌握商家客户的获客渠道，手上有多个客户，我才有拒绝不守契约客户的底气。
- 3、业务能力过关很重要，让更多人知道你业务能力过关同样重要。

小结一下年初我 vibe coding 创业前的情况：

不利条件：

- 1、非程序员出身，没有大项目开发经验。
- 2、没有什么资金。
- 3、没有流量入口。

有利条件：

- 1、了解电商商家的需求。
- 2、开发过电商小工具，有一定 vibe coding 经验。
- 3、快速入门一个行业的学习能力。

假如我选择不熟悉的细分赛道，试错时间和试错成本都会比较高，未来的不确定性更高，在资金不足的情况下，成功率微乎其微。

结合三条有利条件，我选择了电商AI生图网站的项目。核心业务的技术原理不复杂（提示词+API调用），从 GitHub 或市面上的工作流模板中找到相同的业务逻辑或提示词就能解决。

流量入口是我的硬伤。这里我选择分两步走：短期选择混电商社群，和各个电商博主谈合作；长期我需要自己做自媒体，或者自己建立推广团队。

# 五、复盘总结

1、本项目从开发到上线用了14天，新项目2.0版本我把时间缩短到了三天，并且前端UI有了质的提升。vibe coding开发时间和成本压缩到极致，在产品一块，就有了近乎无限的试错资本。

总业绩的大头，做项目，不仅要做产品开发，还需要找到你的流量操盘手。（2.0 版本在摸索培养素人分销的模式，等过几个月，拿到结果再来分享 2.0 版本）
