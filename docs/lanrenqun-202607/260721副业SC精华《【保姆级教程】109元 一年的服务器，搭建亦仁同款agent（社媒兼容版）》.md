### 01 从一个双击说起

先说我的一个日常动作。

我 iPhone 设置了「背板双击」：看到好东西——一篇公众号文章、一条抖音、一个小红书笔记——复制链接，手指在手机背面敲两下，链接就飞进我的飞书群里了。这个快捷指令我叫它「万物归虾」，看到什么，先归虾。

这个动作本身很爽，一秒钟完成收藏。

但问题是：然后呢？

然后就没有然后了。链接躺在群里，和我微信文件传输助手里的另一批、各个 App 收藏夹里的又一批，一起吃灰。收藏的那一刻我是真心想看的，但「想看」和「看了」之间隔着一条河，河上一直没有桥。

![](img/47426aef198cc16a9b688bd6356cc2e4_0_0.png)

转机是前两天看亦仁直播。原来亦仁分享「小D」搭建思路的那篇帖子其实已经发了一个多月了，我是直播的时候才注意到，当天就去翻了他的搭建文档（生财站内：《小D 复制部署说明：音视频转录整理 Agent》https://shengcaiyoushu01.feishu.cn/wiki/VsEawZUYMi4CCxkjNEncXPJ4nsg ），照着搭了一个。

搭完那一刻我意识到：河上的桥有了。我懒的做的事，有人做好了。

小D 的思路是：丢一个音视频链接给 agent，它下载、转录、把口水话和时间戳洗掉，还你一份「分享式提纯稿」——不是三句话摘要，是原话、案例、关键判断都在的可读文稿。

不过针对我的内容产出和收藏场景，有时候看到好的教程，想要发给我的 hermes 让它学习一下，但是它没有眼睛学不了。于是就有了这篇帖子要分享的升级版。

我收藏的东西里，音视频只是一半，另一半是公众号文章、小红书笔记、抖音视频、视频号——这些不是「转录」问题，是「采集」问题。而且我平时做内容和选品，本来就要搜笔记、挖评论区、拆对标账号。

所以一个升级：我给它写了一个四平台采集的 MCP，直连 TikHub 的官方 API，20 个工具，每个平台都配齐「搜索 / 内容详情 / 评论 / 博主」四类能力：

| 平台 | 搜索 | 内容详情 | 评论 | 博主 |
| :--- | :--- | :--- | :--- | :--- |
| 小红书 | 搜笔记、搜博主 | 笔记详情（贴分享口令就行） | 一级评论+二级回复 | 主页+笔记列表 |
| 抖音 | 关键词搜索 | 分享链接直取视频数据 | 评论 | 主页+作品列表 |
| 微信公众号 | 搜一搜搜文章/搜账号 | 文章链接直取完整正文 | 文章留言 | 账号文章列表 |
| 微信视频号 | 搜一搜搜视频 | 作品详情（贴分享短链就行） | 作品评论 | 主页+作品列表 |

注意一个细节：四个平台都支持「丢链接直接取内容」。这正好接上「万物归虾」——群里躺着的每一条链接，agent 都认得出来是哪个平台、都能把内容拉回来。然后这部分社媒笔记的采集收录都放到多维表格里。这些平台字段是我自己测试过的，提取了 tikhub 返回的这些平台的一些共性字段，这样才比较好写进同一个多维表格里。

于是流水线就通了：

```
手机背板双击 → 链接进飞书群 → agent 拉内容 → 转录/整理成稿 → 归档
```

「收藏了从没看过」，变成「收藏了 ai 看过并记录下来」。

### 05 我替你踩过的三个坑

这套东西发出来之前，我全部用真 key 实测过一遍，测试时踩了三个坑，都替你填好了：

- **坑一：403 Forbidden**。第一次调 TikHub 就翻车，查了半天，是它前面的 Cloudflare 把 Python 默认的 User-Agent 给封了。不修这个，你照任何教程写都会卡死在第一步。仓库里的代码已经带了正确的 UA。
- **坑二：接口 404**。TikHub 官方 SDK 里微信侧的接口路径全是旧版，照抄全是 404。正确路径要以它线上的 OpenAPI 规范为准（v2 前缀）。仓库里已经全部对齐线上版本，四平台 20 个工具，主链路全部拿真 key 实测过——公众号那条我就是拿自己的文章测的，完整正文一次拉回。
- **坑三：转写费钱费时**。长音频扔给转写又慢又费。解法就是前面说的字幕优先：先拉字幕，拉不到再转写，短的服务器 CPU 硬跑，长的接云端语音识别按量付费。这条已经写死在 agent 的指令里，它会自己按这个优先级来。

### 06 装完之后的进阶玩法

给几个我自己在用的话术，直接抄：

**收藏清理（配合定时任务）**：

```
每天早上八点，把昨天飞书群里的链接逐条拉内容，音视频出提纯稿，文章出要点归档，整理成一份日报发我。
```

（Hermes 的定时任务用大白话就能设，不用写 cron 表达式。）

**跨平台选题调研**：

```
「手冲咖啡」这个方向，小红书和抖音各搜一页，归纳两边的爆款角度差异，给我 3 个能直接用的选题。
```

**评论区监控/挖需求**：

```
帮我监控，这几篇笔记是否有新评论。把评论和高赞的二级回复拉下来，提炼高频问题、抱怨点和购买信号，用户原话保留。
```

**对标账号拆解**：

```
这个博主的主页和最近的笔记列表拉一下，归纳他的内容支柱、发布节奏，说说哪些可以学、哪些不该学。
```

采集是按次计费的，agent 的指令里我写了花钱纪律：先小样本看方向，复用数据走免费的 cache_url，每轮汇报调用了多少次。你的钱，它省着花。
