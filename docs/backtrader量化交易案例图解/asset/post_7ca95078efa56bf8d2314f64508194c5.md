## 11.4 实盘交易及其隐性规则

目前，大家对于BackTrader的使用属于准实盘交易阶段，准实盘交易和实盘交易最主要的差别在于以下两个方面：

- 数据源的实时更新。
- 操作资金的实际投入。

如果做实盘交易，必须使用每天的最新数据。在第11.3节案例程序的输出信息中，在2018年12月18日有交易数据，如果在18日收盘时运行这个程序，程序会推荐买入股票代码为2046的股票（买入价格是6.78元），再通过交易软件设置买单就可以了。

如图11-4所示是BackTrader量化软件中的交易子模块架构图。

![](img/1c2fa9d9dc5f4ecf1f6a4ce7faab4913_273_0.png)

图11-4 交易子模块架构图

原生版的BackTrader量化程序，对于股票池的支持不好，可以在BackTrader量化程序的基础上增加一个for外循环。

在实盘操作中，一些实力雄厚的金融团队会把市场中所有的交易股票作为股票池，系统本身没有预设的股票池，把所有的交易股票作为输入数据，这就是所谓的全市场模式。

这种全市场模式还可以做二次筛选，类似于单因子分析，就是与前几天的收益做对比。

进行量化交易实盘操作时还有一些潜在的隐性规则。

第一个隐性规则是交易使用的策略是通过测试的，也是通过参数优化的。比如，MA均线策略内置的时间周期参数是15天，但默认的15天不一定是最优解。

第二个隐性规则是缩短回测周期，提高回测分析速度。

第三个隐性规则是注意Position检查。

图11-5所示是Position子模块关系属性示意图。

## 图11-5 Position子模块关系属性示意图

由图11-5可以看出，其主要相关的子模块库有LineBuffer、Order、Sizer、Trade等。

在Position仓位管理子模块中最常用是getposition函数。getposition函数用于读取当前仓位数据，其实是position内部变量的二次封装。

此外，使用BackTrader的position类函数还可以看到买入时的价格，随时根据平均仓位成本进行操作。

下面再看看案例策略源码，position函数主要用于next函数：

```
# 检查当前股票的仓位 Position
    if not self.position:
        # .
        # 如果该股票仓位为 0，则可以进行 Buy 买入操作
        .....
    else:
        # 如果该股票仓位>0，则可以进行 Sell 卖出操作
```

在执行买卖交易的时候，需要确认当前的 Position 数据，检查 Position，只有持有当前股票才可以进行卖出操作，如果没有持有当前股票就无须进行后续的操作，这也可以提高回测运行效率。

在 next 策略函数运行时，相关的数据源、指标参数都已经在 init 函数中设置完成了。

在默认情况下，BackTrader 量化程序不支持空头交易，需要通过参数设置调整，必须持有股票才能卖出，即 position 函数必须处于非零状态，才能进入卖单操作，但买单没有限制。

当 position 函数检查仓位数不为零时，系统自动运行，转到买入操作流程，进行买单操作。

BackTrader 的 Position 很灵活，用户可以自行设置，例如按持仓 100 手以上或者超过多少资金再进行卖出，也可以按当前持有现金的比例购买股票。

顺序，先到先得。
