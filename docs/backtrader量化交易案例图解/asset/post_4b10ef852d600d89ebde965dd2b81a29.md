由图13-11可以看出， SignalStrategy信号策略类隶属于Strategy类，其主要相关子模块库有Analyzer、Order等。

案例相关程序代码如下：

```
# 创建一个SignalStrategy最简单的信号策略类
# 用于输出买卖执行信息
class sgn_st001(bt.SignalStrategy):

    def notify_order(self, order):
        # 检查订单order是否完成
        if order.status ==order.Completed:
            xss=''
            css=',成交价: {:.2f},小计 Cost: {:.2f},佣金 Comm {:.2f}'.format(
            order.executed.price,order.executed.value,order.executed.comm)
            if order.isbuy():
                xss='买单执行 BUY EXECUTED'
            elif order.issell():
                xss='卖单执行 SELL EXECUTED'

            #
            tim=format(order.data.datetime.datetime())
            tss=tim+',@ '+xss+css
            print(tss)
```

sgn_st001自定义信号策略类包含了一个notify_order订单处理函数，用于处理交易订单信息。
notify是通知的意思，表示传递订单处理信息，而不是执行的意义，因为订单的执行是在后台自动操作的。
notify_order订单处理函数的作用是，当订单完成时检查订单状态，查看是买单还是卖单。
然后输出订单信息，大家可以参考相关源码，包括交易时间、价

位、佣金等数据，具体代码如下：

```
css=',成交价: {:.2f},小计 Cost: {:.2f},佣金 Comm %:{:.2f}'.format(
    order.executed.price,order.executed.value,order.executed.comm)
```

上述输出信息只有订单执行的数据，没有订单设置的数据，这也是一个小bug，大家可以在策略函数中进一步细化，增加订单设置的数据。

再看看买入订单、卖出订单的操作。
通过主流程的add_signal添加信号函数，设置买入订单、卖出订单，无论是多头还是空头，都使用这个信号交易函数。

> 信号交易函数的数值大于0，买入；小于0，卖出。

信号交易函数返回值并非是一个固定数值，可以视为一个动态数据或者一组数据，在BackTrader量化软件内部对应一组数据lines。
信号交易函数的返回值采用了布尔逻辑运算，只取返回值的状态：大于0，小于0或者等于0。如果需要更细化的操作，则可以做进一步的处理。

add_signal添加信号函数用于在主流程中设置自定义信号函数。此外，本节案例只有订单执行的价格等信息，还不完善，应该再增加订单设置的信息。否则，在进行实盘操作时会有很多限制。

在传统的交易模式中，所有的自定义函数都放在一个策略类中，方便进行策略编程和管理。笔者个人认为，BackTrader量化软件的信号交易模式，对于多策略组合交易更加方便。

在实盘操作中，目前更多的是使用传统策略交易模式。传统策略交易模式对于初学者来说比较复杂，不过通过策略模板进行编程就非常简单了，只要修改next函数和init函数的参数设置代码即可。

# 14.1 参数寻优概述

参数寻优也称为参数自动优化，对于量化策略的设计与优化非常重要。

在前面章节的案例中对手动参数优化测试进行过讲解，过程很复杂，而且结果不一定是最优解。

BackTrader量化软件也集成了参数优化功能，但需要注意的是，其自带的参数优化函数optstrategy存在小缺陷：在多核模式下，optstrategy参数优化函数有时无法运行，所以在参数优化案例中，使用TopQuant极宽量化团队开发的opt参数优化程序。
