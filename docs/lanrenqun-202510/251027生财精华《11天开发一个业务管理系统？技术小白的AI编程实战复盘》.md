恰好几天前刚参加完生财的 Claude 航海，学会了 Claude Code 的基本用法。我突然想：既然都学了，为什么不试着让它帮我开发一个专属于自己业务的管理系统？

## 一、转折点：生财航海的触动

其实在这之前的9月，我刚参加完生财有术的 Claude 航海(2025.09.03 - 09.25, 23 天)，学习 Claude Code 的基础操作。

当时抱着学习的心态去的，想看看 AI 到底能干什么。航海里学到了很多实战技巧，打下了基础。

后来在刘小排老师的公众号文章里，看到他讲的**"plan 模式+狂暴模式"**组合，印象特别深：

- Plan 模式：先把需求聊透，完全理解业务逻辑
- 狂暴模式：再让 AI 快速开发

当时听着很有道理，但没想到自己会真的用上。

### 为什么决定自己做？

那个崩溃的周末之后，我想：既然学了 Claude Code，为什么不试试开发一个真正适合自己业务的系统？

我做的是知识服务/咨询业务，流程其实很简单：

> 客户询价 → 我报价 → 接单 → 制作内容 → 交付 → 收款

但市面上的通用 CRM：

- ✘ 功能 90%用不上，反而增加操作复杂度
- ✘ 真正需要的功能没有，或者要花钱定制
- ✘ 月付费还不便宜

### 如果能自己开发，完全按照我的业务流程来设计，那该多好？

## 二、准备阶段：磨刀不误砍柴工

### 第一步：用 ChatGPT 梳理需求

我没有直接开始开发，而是先花了几天时间梳理需求。

打开 ChatGPT，跟它一遍遍地聊我的业务：

> "我的业务流程是这样的...我遇到的问题是...我希望系统能帮我做什么..."

ChatGPT 不断问我细节，我就不断补充。聊了大概 3-4 个小时，最后让它帮我整理了一份开发任务书。

![](img/f79e4c3635a13788dc5a3c9d22f3be9b_2_0.png)

这份任务书很关键，它让我第一次把自己模糊的需求变成了清晰的文字。里面包括：

- 核心功能清单（客户管理、订单管理、财务统计等）
- 每个功能的具体需求（比如"客户信用管理"要能标记坏账、自动预警）
- 数据之间的关系（客户-订单-收入-支出如何关联）
- 使用场景描述（什么时候用、怎么用）

### 第二步：Codex 的短暂尝试

有了任务书，我开始准备开发。

但一开始我没搞定 Claude Code 的部署，就先用了 Codex(另一个 AI 编程工具)。用了几天发现效果不太好：做出来的东西跟预期不太一样，沟通不够充分，调试也比较麻烦。后来搞定了 Claude Code 的部署，就转过来了。

### 第三步：Claude Code 正式开始 (2025.10.11)

这次我学聪明了。打开 Claude Code 后，我没有直接说"帮我开发系统"，而是先用 plan 模式，把那份开发任务书作为基础，跟 Claude 详细讨论：

> "我先不急着开发，我们先讨论一下方案。我的业务是这样的...(描述业务场景)...你觉得应该怎么设计这个系统?"

Claude 开始问我各种细节问题，我们就像两个人在讨论项目一样，把整个系统的架构、数据结构、业务逻辑都聊清楚了。

讨论许久，我感觉 Claude 完全理解了我的需求。

这时候我说："好，现在开始开发吧。" 然后切换到狂暴模式，让它逐项开发。

## 三、核心心法：你是老板，Claude 是员工

在讲具体开发过程前，先说一个最重要的认知：

很多人以为用 AI 开发就是"告诉它做什么，它就做什么"。

错了。

正确的关系是：你是老板，Claude 是技术全能的员工。

### 这意味着什么？

#### Claude 的角色：

- 技术能力全面，执行力强
- 会给你专业建议
- 能快速实现你的想法

#### 你的角色：

- 业务专家，最懂自己的需求
- 方向把控，做最终决策
- 判断 Claude 的建议好不好

#### 关键：

- ✓ 你的思路必须清晰，逻辑不能乱

Claude 会给建议，但采不采纳是你决定。就像招了个技术总监，但公司方向还是老板定。

### 举个例子

> Claude："客户等级可以分 4 档：铁牌、铜牌、银牌、金牌"
> 我："不，我的业务简单，分铁牌、银牌、金牌就够了。铜牌听起来太 low。"
> Claude："好的，那我们就用铁牌、银牌、金牌。"

看到了吗?Claude 给建议，但最终判断是我做的。因为我最了解业务情况和客户需求。

这个认知很重要!

- 不要盲目听 Claude 的
- 也不要不听 Claude 的
- 要有自己的判断力

## 四、开发过程：4 个业务痛点的解决

开发周期：2025.10.11 - 10.22，11 天

这 11 天我每天投入 3-4 小时。但不是一直盯着，而是：

> 我提出要求 → Claude 开发(等待) → 我测试反馈 → Claude 修改(等待) → 继续...

这个过程效率很高,因为 Claude 开发的时候我可以去忙别的事,不耽误业务。

每个功能的开发流程都是:先 plan 聊透 →再开发 →测试 →迭代

### 5.1 痛点1：数据分散，手动关联→自动数据关联

#### 业务场景

以前我的数据分散在4个表:订单表、收入表、支出表和客户表。

每次操作都要在四个表之间来回切换:

新客户来了,先在客户表里记录基本信息。接单了,在订单表里新建,手动输入客户微信号。收款了,在收入表里记录,又要手动输入客户微信号和订单编号。经常打错字,比如客户微信号"wxid_abcl23"打成"abcl23",导致数据对不上。想查某个客户总共做了多少单、赚了多少钱,要在三个表里找半天。

#### 我怎么跟Claude描述的(plan模式)

我用plan 模式跟 Claude 说:

> "我希望系统能自动关联数据。我的业务流程是:客户通过微信联系我,每个客户有唯一的微信号。一个客户会有多个订单,一个订单会有收入记录和支出记录。我希望创建订单的时候,输入客户微信号,系统自动判断:如果这个客户以前没有记录，自动帮我建一个;如果已存在，自动关联。"

> 我打开客户详情，就能看到这个客户的所有历史订单、累计做了多少单、总共赚了多少钱，不用我手动统计。

#### 聊透边界情况

Claude 问："如果客户微信号输入错了怎么办?能修改吗?"

我说："能修改，但要提醒我这个客户已经有关联的订单，修改后所有订单的客户信息都会更新。"

Claude 又问："累计收入是统计所有订单，还是只统计已收款的?"

我说："只统计已收款的，没收到钱不能算收入。"

#### 实现效果

现在系统做到了真正的数据关联。我创建订单只需要输入客户微信号一次，系统自动处理后续关联。

客户列表里，每个客户旁边直接显示"累计订单数"和"累计收入"，点进详情页能看到所有历史记录。再也不用在多个表之间跳来跳去了。

![](img/f79e4c3635a13788dc5a3c9d22f3be9b_7_0.png)

### 5.2 痛点2：报价计算费时间→自动计算+客户折扣

#### 业务场景

每次客户询价，我要拿计算器算。比如客户要 5000 字的内容，我的基础价格是 100 元/千字，算下来 500 元。

如果需要提供参考资料，加 50%，是 750 元。如果还需要翻译部分内容，再加 10%...

而且老客户应该有优惠，做过 3 单的打 95 折，做过 10 单的打 85 折，但每次我都要先查客户做过几单，再手动算折扣。

#### 我的自然语言描述

> "我希望在创建订单的时候，输入字数，系统自动算出建议报价。"

> "报价规则是：基础 100 元/千字。如果勾选"需要资料"，价格×1.5;勾选"需要翻译"×1.1;勾选"需要数据分析"×1.5。这些系数可以叠加。"

> "另外，系统要自动识别客户等级：完成 3 单以上是银牌(95 折)，完成 10 单以上是金牌(85 折)。报价的时候自动应用折扣，但我还能手动修改最终价格。"

#### Claude 提问边界情况

> "如果客户做过 3 单但有 1 单没付款，算不算银牌客户？"

我想了想："只统计已完成收款的订单，没收钱的不算。"

> "折扣是在附加系数之后应用，还是之前？"

"之后。先算附加服务，最后再打折。"

#### 实现效果

现在创建订单时，我输入字数 5000，勾选"需要资料"，系统瞬间显示：

> 建议报价：¥712.50

(基础¥500 × 1.5 附加系数 × 0.95 银牌折扣)

我可以直接用这个价格，也可以根据客户关系手动调整。报价速度从 2 分钟变成 5 秒。

### 5.3 痛点3：坏账管理混乱→自动预警+信用追踪

#### 业务场景

最头疼的是遇到不付款的客户。之前有个客户订单完成了不给钱，我在 Excel 里标记了一下。结果这个月他又来新单，我忘了之前的事，又接了，结果又不给钱。

一个客户连续欠我两笔，我才反应过来。但为时已晚，又浪费了时间和成本。

#### 详细的需求描述

我跟 Claude 说：

> "我需要一个客户信用管理功能。如果某个订单收不到钱，我把它标记为坏账。系统要自动把这个客户拉黑，在客户列表里用红色高亮显示，一眼就能认出来。"

> 最关键的是：下次这个客户再来询价，我创建订单输入他的微信号时，系统要立刻弹窗提醒我：'⚠️ 警告!该客户有 X 笔坏账，欠款 XX 元，强烈建议不要接单!'

> 但我要能选择继续接(有时候客户只是暂时资金紧张，后来会给钱)，不能直接阻止我创建订单。

> 如果客户后来把欠款给了，我录入收款后，系统要自动检查：他还有没有其他坏账?如果全部清了，自动恢复信用，取消红色标记。"

#### 边界情况讨论

"如果客户有 3 个订单，1 个坏账，2 个正常，算不算黑名单客户?"

"算!只要有 1 个坏账就要警告。"

"坏账订单如果后来取消了(比如协商不做了)，还算坏账吗?"

"不算。取消的订单就当没发生过。"

"客户只给了一部分钱呢?"

"我录入实际收款金额，只要有收入就解除坏账状态。"

#### 实现效果

现在系统自动管理客户信用。坏账客户在列表里红色高亮，创建订单时会弹窗警告，我再也不会忘记了。

而且我发现，客户列表上直接显示每个客户的"坏账订单数"，有些看起来正常的客户其实有1笔坏账，我会更谨慎地对待。

### 5.4 痛点4：数据统计全靠手动→仪表盘自动汇总

#### 业务场景

每个月底我要看经营数据：这个月赚了多 少?花了多少?利润多少?完成了几单?

以前要打开收入表，筛选本月数据，用 SUM 函数加总。再打开支出表，筛选本月，加总。两个数字手动相减算利润。

想看本季度的?重复一遍，筛选条件改成3个月。想对比去年同期?更麻烦，要找去年的表格…

每次对账要花1-2小时，而且容易出错。

#### 我的需求

> "我想要一个首页，打开系统就能看到关键数据。最重要的指标是：
> 收入、支出、利润(自动计算)
> 已完成订单数、未完成订单数
> 超期订单数(应交付日期过了但还没交付的)
> 坏账金额
> 
> 要能切换时间范围：本年/本季度/本月/自定义。点一下按钮，所有数字自动重新计算。
> 最好还能对比去年同期数据，显示增长率，这样能看出业务是在增长还是下滑。"

#### 实现效果

现在打开系统，首页就是12个核心指标，排成两行。点击"本月"按钮，瞬间看到当月所有数据。

每个指标都能点击展开详情。比如点"超期订单3个"，立刻展示是哪3个，我可以马上跟进。

月底总结从2小时变成5秒钟，而且数据绝对准确，不会算错。

## 五、我总结的沟通技巧

开发了11天，我总结出一些跟Claude沟通的技巧。有些是从刘小排老师公众号文章学的，有些是自己摸索的。

### 技巧1：记住，你是老板，Claude 是员工（最重要的一条!）

不要盲从Claude的建议，也不要完全不听。要有自己的判断力。

你最懂业务，Claude 最懂技术。结合起来才能做出好系统。

### 技巧2：Plan 模式是关键，先聊透再开发

这是我从刘小排老师公众号文章里学到的"plan+狂暴"组合拳：

#### Plan 阶段(20-30 分钟)：

- 详细描述业务场景
- 讨论实现方案
- 确认边界情况
- 理清数据逻辑

#### 狂暴阶段：

"好，需求我们已经讨论清楚了，现在请你开始开发"

Claude 会快速生成代码

这个组合拳的好处是：plan 阶段保证方向对，狂暴阶段保证速度快。虽然前期多花时间聊，但后面少改很多次，总体更快。

### 技巧3：讲故事，不要列功能

错误示范："我要客户管理、订单管理、财务统计。"

正确示范："我经常遇到这样的情况：客户微信发来新单，我要先查 Excel 看这个客户之前有没有欠款。查完了再记录新订单信息，手动输入客户微信号，经常打错字。我希望系统能自动关联，我输入微信号就自动显示客户的历史记录和信用状况，然后创建订单。"

用具体场景描述，Claude 更容易理解你真正需要什么。而且在描述场景的过程中，你自己也会把业务逻辑想得更清楚。

### 技巧4：说清楚边界情况(edge case)

正常情况 Claude 都能处理，关键是特殊情况。比如坏账管理功能，我会主动说：

"客户欠钱了怎么办?"

"客户后来把钱给了呢?"

"如果订单取消了还算不算坏账?"

"如果客户有多笔订单，部分坏账部分正常，怎么处理?"

把这些"万一"都说清楚，Claude 才能设计出完善的逻辑。不然开发出来后遇到特殊情况，系统就不知道如何处理了。

### 技巧5：遇到 bug，用自然语言描述问题

系统肯定会有 bug。比如我发现客户等级有时候不会自动升级，我就跟 Claude 说：

> "我发现一个问题：有个客户明明做完了第 3 单(已收款)，按理应该自动升级到银牌，但系统还显示铁牌。我在客户详情里看了，确实有 3 条已完成的订单记录。是不是自动升级的逻辑有问题?"

说清楚三要素：

- 1. 现象：客户还是铁牌
- 2. 预期：应该是银牌
- 3. 证据：确实有 3 条已完成订单

Claude 就能定位问题。我完全不需要看代码，不需要懂技术术语。

### 技巧6：工具要用好的

这是血泪教训!

我一开始用第三方限额版本的 Claude，体验很差，经常卡，响应慢，效果也不好。

后来换成拼车，体验好很多。

还试过 Codex，实测下来还是 Claude Code 最顺手。

别在工具上省钱，否则浪费的时间更不值。搭了时间不出成果，才最尴尬。

### 技巧7：小步迭代，持续打磨

系统不是一次做完的:

最开始只有客户管理和订单管理

用了几天发现需要坏账管理，加上了

后来又觉得需要返佣功能，再加

现在已经 v1.1.2 版本

Claude 可以在现有系统基础上持续迭代，不用推倒重来。

先做能用的，再慢慢完善。

## 六、效果回顾：用了几天的感受

回到开头场景

现在又是周末，我打开电脑。

不再是打开 Excel 一个个表格查数据，而是打开我的系统。

点一下"本月"，所有数据自动显示：收入、支出、利润、完成订单数...5秒钟，完成。

以前那个对账对到崩溃的周末，感觉像是上辈子的事了。

### 主要改善

#### 1. 及时提醒，不再遗漏

以前全靠脑子记：哪个订单快到期了？哪个客户该催款了？经常忘。

现在系统会提醒：超期订单、未结算订单，一目了然。

#### 2. 数据统计准确

以前手动算，经常出错。现在系统自动计算，错误率 0。

任何时候都能准确知道：这个月赚了多少，利润多少，业务状况如何。

#### 3. 实现了一直想做的功能

**客户分级功能：**

以前就想给老客户打折，但受限于脑子记，不好统计谁做了几单。

现在系统自动识别：做过 3 单以上自动变银牌(95 折)，10 单以上自动变金牌(85 折)。报价的时候自动应用折扣，省心又准确。

**返佣功能：**

以前有客户推荐新客户来，我说要给返佣，但经常忘记或者算不清。

现在系统有返佣管理：记录谁推荐了谁，返佣多少，什么时候给的，清清楚楚。

### 后续更新思路

系统已经够用了，但还想加点功能：

慢慢来，不急，先把现在的用熟了再说。

## 七、关于数字化赋能的一点思考

用了自己的系统后，我有了一个新认识

以前我一直觉得公司花上百万买的 OA 系统不好用。界面挺漂亮，功能也全，但大家还是习惯用 Excel。

我当时想：这些 OA 系统都是摆设，中看不中用。

但是自己开发完系统，用了几天后，我的想法变了

我才真正体会到信息化的提质增效：

- ☑ 数据自动关联，不用在多个表之间跳来跳去
- ☑ 统计自动计算，月底总结从 2 小时变 5 秒
- ☑ 及时提醒，不再遗漏重要事项
- ☑ 客户分级、返佣这些功能，以前想做但做不了，现在轻松实现

效率提升不是 10%、20%，而是数倍甚至数十倍。

### 那为什么公司 OA 没有这个效果？

我现在理解了：不是 OA 系统不好，而是系统和业务两层皮。

OA 设计得很通用，适用各行各业，但也意味着：

- 很多功能用不上，增加操作复杂度
- 真正需要的功能没有，或者要花钱定制
- 流程是标准化的，但业务是个性化的
- 不是为我们的业务设计的，是我们在迁就系统

### 我的系统为什么有用？

不是因为我技术多强(我完全不懂代码)，而是因为：

- ☑ 我最懂自己的业务
- ☑ 每个功能都针对真实痛点
- ☑ 我每天用，发现问题马上改
- ☑ 系统完全贴合业务，不需要迁就

### 核心认知

> 如果想用信息化、数字化、AI 化赋能业务，老板必须要：

> 1、清楚业务流程和业务逻辑
> 2、深度参与系统设计和打磨
> 3、不断根据实际使用反馈调整

否则就是系统挺好看，说起来也挺好，但员工还是用 Excel 干活。

数字化不是买个系统就完事了，核心是业务逻辑的梳理和固化。

AI 工具让技术门槛降低了，但业务门槛没变。最懂业务的人，应该深度参与甚至主导系统开发。
