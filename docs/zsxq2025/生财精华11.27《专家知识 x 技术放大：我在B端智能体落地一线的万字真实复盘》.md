## 我所到的智能体落地的B市场

最近两年，我一直在智能体落地这个赛道上摸爬滚打。
从最初在扣子平台上瞎探索，做到平台 TOPI 的开发者，开始接一些小B的定制单。再到后来入职一家专做B端落地的公司，全职服务企业客户。可以说见证了从小B到大B的不同需求，也跳过了各种规模客户的坑。

目前主要服务央企和头部公司，行业集中在金融和能源化工两个方向。从这些项目里，我看到了一些很有意思的现象。

### 1.1 企业采购的两种典型路径

从采购和落地形态上看，企业大致分成两类：

**A类企业：先买平台，再顺带买几个智能体**

典型路线是技术部门牵头采购低代码平台（类似于扣子、Dify这类），目标是建一个“集团通用底座”。采购完成后，业务部门各自拿平台试着搭几个场景。
实际结果往往不如人意。场景非常浅——翻译、OCR、小知库、简单问答，基本都是入门级应用。工作节奏少、调用链短，几十万的平台只能发挥了一点点。更要命的是，人员缺乏专家流程和评估标准，导致系统“能跑”但不好用”。

这类企业不是没投入，而是投入位置不对——买了底盘，却没人会开车。

**B类企业：不买平台，直接买智能体项目**

这类企业又分为两个终端。

一种是保守派，他们特别务实。从小场景、试验性场景切入，比如在 OA 系统集成语音交互功能，让员工用自然语言发起请假、差旅申请。这类客户是最成熟的——从简单可控的点开始，验证效果后再逐步深入，一点探索 AI 的边界。风险可控，容易形成循环。

另一种是激进派，这类同样愿意买单，但边界感为零。他们会要求智能体模型根本做不了的事，比如产品推荐、策略决策，把算法系统和 LLM 混为一谈。或者把“知识库正确率95%”当理所当然的目标，却不理解数据质量、检索策略、路径这些问题。最让人疼的是，他们不愿意向流程里投放专家时间，却要求产出达到专家级别。

这类客户交付风险高，项目常常变成“许池”，不是工程。

### 1.2 市场的真实问题

把这些现象重构成一句话：企业端的真实问题不是“缺技术”，而是“缺边界的清醒认识、缺乏专家流程写进系统的能力”。

你只要在交付现场对待，就会发现才是决定项目成败的总开关。技术反而是相对简单的部分——大模型能力摆在那里，工作流平台也很成熟。难的是如何让企业理解 AI 能做什么、不能做什么、他如何把他们脑子里的专家知识变成可执行的系统流程。

这就是 B 端智能落地的现状——机会很大，坑也很多，关键看你能不能找到对路径。

## 二、“好用、能落地”的智能本质：专家知识 × 技术放大

企业真正能用起来的智能体，本质只有一件事：把“专家做事的套路”变成“机器可稳定执行的流程”，再用技术把它放大到规模、低成本。你可以把它压成公式：

好 Agent = 专家知识（业务 SOP/判断标准） × 技术能力（提示词/工具/系统集成）

注意这里是乘法，不是加法。一边是 0，整体就是 0。

### 2.1 专家知识是什么

很多人以为专家知识就是“资料多”或“懂行业术语”，错了。真正落地的专家知识，是两类东西：步骤拆解和完成标准。

- **步骤拆解（SOP）**：知道这件事要按什么顺序做，比如法务审计的流程。
- **完成标准（验收口）**：不仅要知道做什么，更要知道清楚结果算合格、什么算异常、哪些字段必须准确。

专家做了太久，很多判断已经内化成直觉和肌肉记忆，如果不经过结构化引导、反复拆解，永远进入系统。所以专家知识不是“文档堆砌”，而是“套路”。没有这套标准，你的智能体就是个玩具。

### 2.2 为什么专家知识比技术更关键

企业端技术往往不是难点。真正让项目死掉的，是没有人能清楚怎么做、后做什么。所谓“自由发挥”等于“不可控”。客户要的是确定性，不是创造性。

很多团队做 B 端失败——他们有技术但没有专家知识，连流程都写不出来。提示词不是文学创作，是把脑里的逻辑抽象成方法，让机器执行。

### 2.3 有了专家未必好使——两个隐藏坑

当然，有了专家也不一定好使，这里有两个逻辑：

第一个坑：专家不愿意配合。理想很丰富：我们把能力给了 AI，就稀释了公司的稀缺性。实际愿意配合的企业少之少，这在是给自己找麻烦。

第二个坑：专家讲不清楚。即便 B端的专家愿意配合，他也可能讲不清楚。这是最隐藏的坑——“隐性知识”。你问他“为什么要先看这个字段”，他说“我就习惯先看”；你问他“什么情况算风险”，他说“看多了就知道了”。所以这类 B 端项目里，有大量时间花在写代码，而是在帮专家把自己的经验翻译成可执行的步骤和标准。

### 2.4 条路径：横着还是竖切

如果你真想把智能落地做好，核心问题是：你有没有专家知识。作为服务商，我们通常有两种做市场的方式——竖着切和横着切。很多人认为这只是市场策略的选择，其实背后是对专家知识依赖的不同。

**竖着切（深耕行业）**

选择你真正懂的行业，深耕下去。比如懂金融，就专做金融；懂制造，就专做制造。这条路看似市场小，但其实更稳。因为专家知识本身就是壁垒。别人想进来，不是买几个模型 API 就能搞定的，他得花时间积累行业认知、跨过行业的坑、理解行业的潜规则。你有了行业知识，就能帮客户做得更深，真正深入到他的业务里去解决问题，而不是在表面搞些花架子。竞争也小，因为真正懂行的本来就少，懂行又技术的更是。客户也更信任你——这个团队是懂我们业务的，这句话值千金。

**横着切（通用场景）**

找一些通用场景，比如智能问答、内容生成、报告生成，适用于任何行业。这条路看似市场更大，所有行业都是你的潜在客户。但问题来了——这是一个充分竞争的市场。大家都能做 RAG，都能接 Deepseek，凭什么选你？

关键的是，横着其实需要专家知识。拿智能答来说，看似都是用 RAG 技术，但有行业经验的团队知道怎么针对特定领域优化分块策略、怎么设计召回逻辑、怎么做领域词表。没有这些，你的问答系统就是一个通用玩具，准确率上不去，客户不会买单。

B端智能落地，本质是“专家流程化”。

这段话值得反复琢磨。你不是在卖技术，你是在把专家的工作方式变成可复制的系统。

## 三、分清两类——自主规划 Agent vs 工作流

企业落地前先分清：交付的是“自主规划 Agent”还是“工作流 Agent”。这两个不是同义词，差异巨大。

### 3.1 自主规划 Agent 是什么

自主规划 Agent 的特点是你给一个目标，它自己决定步骤、自己检索、自己执行。但在企业级场景下问题来了：模型临时决定，输出波动太大，慢且成本高。真正两个场景：
- **Deep Research**（深度调研）：把乱的信息整理成报告。
- **AI Coding**（代码生成）：在代码环境中自我校验。

### 3.2 工作流是什么

工作流走的是另一条路。人先把流程画好：第一步做什么、第二步做什么、每一步输出是什么。这种方式在企业级场景下优势明显，流程透明，每一步都能看到、监控。

### 3.3 为什么企业选择工作流

工作流是现在，自主规划 Agent 是未来。因为企业要的是可控，不会即兴发挥。每一步都是固定的，出问题能快速定位，流程固定后可以针对性优化，持续效果。

## 四、智能体五大落地场景

我把这些里最稳、最常见、容易形成复利的场景分成五大类。

### 4.1 场景一：知识库落地是将有的知识、经验变成“24小时可控的专家”

这一类最稳，因为需求天然存在——所有组织都有知识传递、制度解释、内部培训、客户答疑的需求。从小切入，两三个节点就能跑起来。落地形态包括：
- 内部专家库（制度、流程、培训资料）
- 外部客户库（产品说明、使用手册、FAQ）
- 学习培训助手（课程资料、讲义、题库）

但这里有一个常见错觉：“能回答就行”。实际交付里，70分系统只能算 Demo，企业要的是接近专家水平的稳定性。做到70分很容易，但到90分很困难。难点集中在关键环节：
1. **数据清洗**：数据乱无章、数量庞，Word、PDF、Excel、PPT、插件、手写笔记格式五花门，质量参差不齐。
2. **切块策略**：在语义块、定长切块、滑动窗口之间找平衡。
3. **Query 重写**：用户问题口语化、不精准，需要改写成适合检索的形式。
4. **意图识别**：对用户行为分类，路由到对应的知识库。
5. **混合检索**：向量检索和关键词检索结合，各取所长。

### 4.2 场景二：内容生成（文本/图片/视频）

首先谈营销内容生成，这是最关心的场景。因为内容=流量，流量=收入。
- **营销内容**：写写文案、爆款。
- **视频生成**：自动生成视频内容。

很多人误解，以为给模型一个主题就能自动产生爆款。其实这里有大量的知识和隐性操作：观点支撑、来源标注、风格模仿。

### 4.3 场景三：报告生成

这类场景在金融、政企领域很常见，需要把乱的信息收集成规范的报告。以前需要人工每天盯着，枯燥重复。现在通过智能体自动化完成：信息抽取、填充模板、最后输出。典型链路包括周报、月报、会议纪要。

### 4.4 场景四：内容分析（抽取 / 对比）

比较容易的一类，把非结构化材料里的关键信息变成结构化数据。
- **字段抽取**：乙方、金额、付款条件、违约条款、生效日期。
- **合同对比与风险提示**：大型集团有标准模板，下属公司签合同时会修改。法务需要肉眼对比，现在通过智能自动标出差异条款，解释修改的影响（如账期延后、违约金调整等）。

### 4.5 场景五：自然语言交互

典型的是 NL2SQL（自然语言转查询）。让不懂技术的人也能直接查数据库。业务人员问“上个月华东区销售额是多少”，系统自动翻译成 SQL 并返回图表。

## 五、定价与交付形态——大B逻辑 vs 小B逻辑

B端落地做起来，很多时候不是技术问题，而是交付形态和定价逻辑站错了边。你用卖小产品的方式去卖大企业，死；你做大项目的方式去做小企业，也死。两套商业逻辑本质不同。



安全合规是大 B 项目的第一约束，不是附加项。数据能不能出内网？模型调用是否可追溯？输出是否有审查机制？这些问题答不好，项目直接接黄。更要命的是，大企业的组织协作成本极高。决策链、多部门拉扯、需求变更频繁，即使试点成功也因为内部博弈而死壳。所以大 B 项目更像“政治工程+业务工程+技术工程”的叠加，你不仅要懂技术，还要懂组织、懂流程、懂人性。

### 5.2 小 B（中小企业）要的是标准化服务

小 B 的计价单位是元/月、打包价或套餐。他们决策快、执行猛、离一线，但没有余力陪你做长期共建。这里有个关键洞察：小 B 不仅仅要产品，他们也希望服务。但是问题，如果你给小 B 也提供定制化服务，那就万毫无意义——他们支付不起定制化的溢价，你的成本也覆盖不了。

所以给小 B 的正确姿势是“产品+标准化服务”。产品要直接跑起来，交付当天就能看到效果。服务要能批量交付，比如标准化的培训包、最佳实践模板。你可以把培训做成可选，SAAS 产品你可以自己搜索，高级版包含培训和答疑。

### 5.3 不同客户的切入策略

大 B 和小 B 的切入点完全不同。

大 B，要从“最盯最累固定的体力”下手。为什么？因为大 B 内部对裁人降本“极其敏感”，你直接要替代某个岗位，会触发强烈的组织抵抗。正确的话是找那些没有人愿意干、纯体力、错误成本可控的环节，先把这些智能体顶掉。组织阻力最小，价值最容易量化。

对小 B，直接谈“多产、多成交、少操心”。小 B 老板不在你的技术多先进，他只在乎三件事：能不能帮你赚钱？不能让你少干活？能不能马上用起来？你的语言要贴着业务结果走，别讲技术，讲效果。

如果你面向 B，核心竞争力是交付体系、行业专家能力、工程化能力和长期运维能力，你得有团队、有积淀、有口碑。如果你面向小 B，核心竞争力是场景产品化、模板化、可复制性和上手即用，你得把复杂的东西包装简单，让小 B 也能用。

两边都想吃，就会两边都吃不动。先选一边打仗，建立根据地，再考虑扩张。很多团队就死在定位不清，大 B 的项目用小 B 的方式做，收不到钱；小 B 的客户用大 B 的方式伺候，成本爆炸。记住，这是两个完全不同的生意。

## 六、差异化怎么打——微调、硬件、专家标注的壁垒游戏

端智能落地跨过了“跑通”这道坎，现在不再仅仅是谁能产出工作流的竞争了。要有更强的竞争力，必须找到差异化。接下来的比的不是谁会节点，而是谁能把效果、成本、数据闭环做出结构性优势。

### 6.1 微调模型：从大模型到小模型的降维打击

现在大家都会用大模型做工作流，但这只是起点。真正的竞争力在于谁能用更小的模型跑赢跟大模型一样的效果。

最有效的节奏是两步走。第一期全用大模型交付，目标是跑通价值链。用最强的模型把“流程闭环”可见化，不纠结单次成本，重点是让业务看到“这玩意儿真能干活儿”。客户认可了价值，项目就稳了。

第二期是关键——成本压力出现后，切换到小模型微调化。用户的真实数据做微调或蒸馏，32B级别的模型通常已经够用，部分场景甚至可以在 CPU 上跑。微调模型好处也很明显，响应速度更快、体验更稳定、成本显著下降。

这一步的商业价值非常硬。如果你能证明“小模型+领域微调 ≈ 大模型效果”，企业会把你当长期供应商，而不是一次性项目。因为你帮他解决了持续可用的成本结构，而不是一个 POC 演示。

这里的技术壁垒在于微调能力和数据积累。谁的行业数据越多、微调经验越丰富，谁就能用更小的模型达到更好的效果。这是后来者很难追赶的。

### 6.2 硬件：掌握数据源头的终极武器

软件可以被替换，但硬件一旦部署就很难。硬件不是卖设备，是卖持续领先。以智能品牌为例，在 B 端场景下，想象空间更大。硬件是掌握数据源头的设备，每天都在产生对话、自动转录、自动结构化、自动挂载，让模型变成默认状态。

更重要的是，硬件创造了三层价值：
- 第一层：提升业务，比如流程建议、合规提醒。
- 第二层：帮助管理，从一线反馈中抽象共性问题、优化培训。
- 三层：沉淀行业壁垒，这是未来的燃料。

### 6.3 专家标注：把知识转化成可持续资产

很多企业害怕专家标注，觉得这样浪费时间、成本。恰恰相反，专家标注是 B 端落地提升效果的关键。通过不断迭代，让 AI 接近专家水平：
- 第一轮可能只有 60 分；
- 专家标注变成 70 分；
- 专家标注变成 80 分。

最终，AI 能够自动输出质量，不再需要专家逐个审核。这个过程其实依赖经验的沉淀，这是之前的做法。比如法律场景，如果你团队里有律师标注，数据质量明显好于纯技术团队；做医疗场景，如果你能搞定几个医生标注，你的系统准确就能碾压竞争。

## 七、趋势判断——大模型发展对智能体系的影响

做 B 端智能体落地，很多公司都有隐忧：哪天会被通用大模型取代？这个担心以前真实，但现在的判断是：威胁正在减弱，甚至可能转化为机会。从大模型发展趋势来解释。

### 7.1 大模型能力见，威胁正在减弱

大模型的能力提升已经进入平台期。从 GPT-3.5 到 GPT-4 是质变，但从 GPT-4 到 GPT-5 更像是量变。不是没进步，而是这种进步对企业实际业务的影响有限。你会发现，最新的模型业务指标可能只提升 5%；但如果优化流程、改进数据质量，提升可以到 30%。

关键的是，无论大模型有多聪明，它永远不会自动理解你的业务。它不知道你们公司的审批流程、不懂你们行业的潜在规则、不会学习你们专家的判断标准。这些东西必须通过智能体系来补充。所以模型取代智能体的威胁正在减弱。大模型越来越像通用工具，而智能体是把这个工具用好的专业系统。企业需要的不是更智能工具，而是更专业的解决方案。

### 7.2 垂直化成为大模型公司的新方向

文本大模型这个维度的故事快讲到头了，大模型公司需要新的增长点。第一个方向是做行业垂直模型。你看阿里的通义千问推出了“点金”专门做金融，百度千帆推出“慧金”也是金融垂直模型。为什么都盯着垂直领域？因为通用能力的竞争已经白热化，差异化只能从垂直领域寻找。对智能公司反而是好事，垂直模型让智能体的整体能力更强，而不是被取代。你用通用模型做金融智能体，准确率 70%；用金融垂直模型，准确率能到 85%。客户更满意，你的交付质量更高，这是双赢。

### 7.3 多模态打开智能体新场景
