


# 为什么快速工作比想象中的更重要？

作者: James Somers
原文地址: https://sommers.net/speed-measures

工作效率的最直接好处是单位时间内能完成更多工作。但其意义远不止于此——当你动作迅速时，大脑逻辑可能会降低对新任务的思考成本，从而更愿意主动尝试。

这个逻辑的反面同样成立。假设你每篇博客都要花费半年时间，当某个周日下午想做事情时，你不再考虑写文章，因为大脑早已将其定为“高成本项目”。

糟糕的是，低效率会导致恶性循环。因为快速完成任务的唯一秘诀就是反复练习，而缓慢的效率夺夺了学习机会。

任何硬性遵循的任务清单都会逐渐丧失灵活性。你会有更多加入新任务的动力，而不是会错失机会。

我注意到：回复越快，收到的邮件越多。反复形成了快速的预期，这种预期会刺激他们持续投入。速度快就像捷径，因为心理负担被大幅降低——他们知道会有快速回馈。

互联网已经是常识；服务器延迟会引起用户流失。网站宕机会让人产生焦虑，它会增加用户的负担。我们还能让他们获得许多奖励的机制。

谷歌速度对于我们功能性非常重要。他们意识到，如果速度迟缓，你就不可能去探索。原因是，它鼓励你去尝试，获得反馈，然后再尝试。当这种发现在脑海中时，你知道自己已经在了路上了。从工作到执行之间没有延迟，你会失去寻找某些任务的动力。谷歌速度的预期成为可能。

在工作中，有一个普遍的规律：工作效率的人会被分配更多的工作。当然，人类是懒惰的。他们习惯节省精力。而且，只要想要把工作分配给一个低效率的人，就会让人感到累。当你开始考虑把工作分配给一个低效率的人，你会在脑海中想象可能出现的情况；你会想象一个低效率的人会被会被滥用，仅仅是这些人以后会感到累，而高效的人——哎，他们的时间显得很“便宜”，因为你给他们分配任务，他们很快就会再次。你并没有给他们分配任务去“累赘”，所以，你可以尽可能把任务分配给高效率的人。这是代价的：

这个普遍规律可以被认为：高效系统需要持续维持，低效率陷入资源枯竭。

再两个典型案例：适用于个人，也适用于整个团队。如果客观发现你需要两个月才能接照片，他们就会去别的装修。如果开源项目合并代码缓慢，贡献者就会停止提交代码。响应缓慢的系统是令人沮丧的。他们就像被割了苔的驴，被饥饿吸收气息。他们只能向更机勃的地方寻找。

现在，我正在使用的编辑器功能好像突然变慢了。这让我很痛苦。首先，我想去撤销操作；可能它在潜移中改变了我的工作方式。我感觉自己已经依赖这个功能了。如果我想删除某些内容，又觉得将来可能还会用到，我就会像回80年代那样把它复制到编辑器底部。这一切都是因为撤销功能变得几乎快速，它是一个神奇。你可以随时回到过去，复制一些东西，然后迅速返回。现在，给人的感觉就像走进了死胡同。

任何行动的启动成本（activation energy），可能决定了我们脑海中的实现方案。可能跑步本身并不耗费成本；但是如果它感觉很高，你就会需要更大的意志力去上跑。

缓慢似乎在我们脑海中画出的画面做出了特别的贡献。时间是人类最贵的资源，因此缓慢会额外重视成本影响。当某些任务被标记为“耗时”时，每次都会触发大脑预警，最终导致回避这项任务。

就是速度至关重要的根本原因。

解决方案是：如果你想做多且擅长某事——比如写作，或者修复漏洞——你应该尝试加速去做。

这并不意味着你在心中的成本会降低；它的启动成本会更低。所以你可以做更多。而当做更多（只要是有有意识地去做）时，你就会变得更好。最终，你体会发现越来越快又会变得出色。

快速工作充满乐趣。如果你是一个快速者，你不会拒绝尝试新方法。还会陷入一波的巨浪中。而且因为你的待办清单简单就能完成，你总是想着对要要素加进的事情。随着更多草稿的进行，世界会更加丰富。你会感觉灵活，你足够丰富，所以当一份艰难而漫长的任务出现在办公桌上，你不会害怕。
