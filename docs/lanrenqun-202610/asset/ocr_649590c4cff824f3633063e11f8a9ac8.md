# 先看清哪里反复搬运，再决定软件怎么做

这里面值得做的事情，是把原来散落在不同窗口、靠人来回搬运的环节接到同一个软件里。界面要怎么改，也逐渐有了依据。

但看见流程，不代表我已经听懂了每一个功能。最早一轮明显的理解偏差，就出在“四视图”上：客户说想要这个功能，我当时根本不知道他具体指什么。

我先拿着自己的理解和 AI 对话，也做出了一个版本，随后很快拿给客户看。对方明确指出：这不是他想要的东西，并给了我实际需要的四视图示例。

这次反馈让后续修改有了依据：先按客户的示例重新确认功能含义和目标效果，再继续实现，而不是顺着原来的猜测往下做。
