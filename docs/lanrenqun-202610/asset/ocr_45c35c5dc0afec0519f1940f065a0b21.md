下思考：用户到底会在什么具体场景下，愿意现在就掏钱买？比如□

+   - 是收到面邀以后临时突击？
+   - 是不会回答某类高频问题？
+   - 是想针对某个岗位做专项准备？
+   - 还是单纯觉得“有一套完整知识库好像不错”？

这些问题我并没有思考，而是直接开始了制作，结果就是，前前后后折腾了半个月，产品越做越完整，但制作周期也越来越长。等到终于把产品做完，我整个人已经被制品这件事耗空了，反而没有心力继续写笔记、测试市场。

后来再看，我觉得这里最大的错误不是“没有发笔记”，而是：在需求确定性还不够高的时候，我就提前支付了完整产品的制作成本 经历了这次，我现在会告诉自己：产品制作成本，要跟需求确定性匹配 1、如果是强节点类的产品，最好是利用一些 Skill 提升产出的效率，缩短从“发现需求”到“商品上架”的时间； 2、如果一个产品制作成本比较高，同时需求又没有被充分验证，建议 build in public 笔记先发，产品思路提前发布去，从笔记的数据和评论区可以找到真实的用户需求，再决定接下来这个产品值得投入到什么程度。
