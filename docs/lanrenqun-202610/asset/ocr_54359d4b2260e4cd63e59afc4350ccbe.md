# 我当时在和 AI 的沟通里写过一句话：

> > “让我先理解这个功能具体的含义，我才能把它开发出来。”

我第一次体会到，做初版的价值不只是展示进度，也是让客户尽早指出“你理解错了”。如果不把这个版本拿给他看，AI很可能会把错误方向做得越来越完整。

我的办法是先把上下文留下来。我用 Get 笔记记录沟通过程，把没听懂的地方、对方给的示例和当前做出的版本放在一起，回去再追问。

通常会用到四类材料：

+   - **沟通记录**：对方怎样演示，提过什么问题，为什么要求修改。
+   - **业务材料**：真实脚本、样例和流程说明，尤其是他最近实际做过的一份工作。
+   - **技术基础**：已有源码、接口说明、现在怎么运行、已知有哪些问题。
+   - **参考与差异**：对方指的是哪个参考产品，想接近哪里，现有做法又有哪些不合用。

这些线索让我回去以后还能继续问，而不是离开现场，就只能凭印象猜客户的意思。
