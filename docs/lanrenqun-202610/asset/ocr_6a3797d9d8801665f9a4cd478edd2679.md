建立，也会在细节上流失。

客户问的是“第一步能拿到什么”，系统却推来一套全能方案；原本还在讨论可行性，回复里已经写成“保证增长”。这类错误不是文风问题，而是把客户正在做的判断，换成了我们想表达的答案。

工作台越能批量生产和分发内容，这种偏差越要在流出前被拦住。分享给大家一个三步追问法：

+   - 有没有回答当下的真实问题？
+   - 关键事实能不能找到来源？
+   - 这一 步有没有替我们作出尚未确认的承诺？

这样设关卡，流程不会因为“每一步都要人看”而变慢。

可逆、可核验的步骤先跑起来。会改变客户预期、资源投入和合作关系的决定，留给能承担责任的人。

更进一步，人工审核中反复出现的偏差也不该每次重新解释。

# 3、把每次审核和反馈，沉淀为下一次可用的判断

大部分只要使用过 SKILL 和类似这种 Agent 执行任务的时候，应该都发现了一个问题，就是第一次给你产出的产物，在人工审核后发现有问题，修改过一次，但是系统只把眼前这一份产物改对了。

下次遇到类似任务，负责人还得把同样的话再说一遍。
