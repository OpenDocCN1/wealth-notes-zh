# ## 这是我按照上面流程产出的一个报告

按照 customer-research → content-strategy 的流程拆解：

+   1. 提取 Trigger Event（什么时候突然开始需要资料）
+   2. 提取 JTBD（用户现在真正要完成什么）
+   3. 聚类 Pain Point（卡在哪一步）
+   4. 保留用户原话，判断情绪强度
+   5. 按用户状态分 Persona，而不是按学校/专业硬凑画像
+   6. 将高频问题映射到现有商品可解决的具体环节
+   7. 生成“一个场景 + 一个问题 + 一个明确结果”的商品笔记方向

> > 注：主题之间允许重叠。比如“跨专业用户收到 EY 面邀”同时属于“面邀突击”“低准备度”“Case/Pre 焦虑”。因此本报告中的频次用于判断趋势，不用于做严格统计排名。

# ## 2. 一句话结论

**最近最值得抓的，不是“想进四大的人”，而是“已经收到测评/面邀，突然发现自己不会 Case、不会 Pre、不会讲实习的人”。**

用户需求已经从前期的“我要不要投、背景够不够”明显往后移动到：

+   - 明后天就要面，先准备什么；
+   - Case 一堆材料到底先看什么；
+   - 群面别人都在说，我怎么插进去；
+   - 英文 Pre 怎样在 1 分钟内说清楚；
+   - M 面深挖实习，怎么避免被问两层就露怯；
+   - Par 面为什么一直问动机、规划、其他 Offer；
+   - 自己跨专业、普通 BG、英语一般、大 i 人，短时间还有没有补救空间。

所以商品笔记不要继续写成“大而全的四大面试攻略”，而要改成：

# ## 4. 最近用户画像

# ### Persona A | “突然收到面邀的临时突击型”

# #### Profile

+   - 校招/寒假实习候选人
+   - 已完成网申或测评
+   - 之前准备不系统，甚至第一次参加正式事务所面试
+   - 收到面邀后才开始集中搜索面经、Case、Pre

# #### Primary JTBD

用最短时间搞清楚：这场到底考什么，我先补哪几块，至少不要因为流程陌生和准备顺序错误直接翻车。

# #### Trigger Events

+   - 突然收到 EY/KPMG/Deloitte 面邀
+   - HR 临时电话通知第二天面试
+   - 看到同批次同学已经开始面试

# #### Top Pains

+   1. 不知道短时间先补专业、Case、英语还是自我介绍。
+   2. 面经看了很多，但还是不知道自己真正要练什么。
+   3. 第一次面试，容易把“知道流程”误以为“能现场做出来”。

# #### 情绪关键词

+   - “快速突击”
