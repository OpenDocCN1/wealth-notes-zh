# 把材料交给 AI，先整理需求，再安排开发

比如“重新打包”，我们需要进一步说清楚：客户拿到哪台电脑，照着什么步骤安装，打开以后先做什么？

我的电脑上有开发环境，客户的电脑上可能没有。这个差别如果一直藏在“能打开就行”后面，到交付时就会变成问题。

所以我会先让 AI 还原工作流，找出矛盾、歧义和缺失的信息。这个提问方式可以直接复用：

> > 先别写代码。请结合这些沟通记录、业务样例、已有代码和约束，还原用户实际的工作流程。把已经确认的事实、你的推断、需要我回去追问的问题分开列出来。然后整理第一版：服务谁、跑哪条流程、明确不做什么、最大的未知项是什么，以及由谁、用什么方式判断通过。

我再拿这份问题清单去找客户，把新的确认信息补回来。有些原本很笼统的要求，就能落到实际操作上了。

课程里那句“歧义是最贵的 bug”，我是在这些来回里才真正理解的。最麻烦的返工，有时从双方都以为自己已经听懂的那一刻就开始了。
