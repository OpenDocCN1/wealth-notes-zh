题带回已有流程里重新确认，再修改、复测。最初的版本让理解偏差暴露出来，后续的原型和试用则把入口、分类与操作顺序一点点对回来。它不是一次开发、一次交付就结束的。

# 几轮迭代之后，具体形成了什么交付物？

这次做出来的是 一套用于 AI 漫剧制作的 Windows 桌面工作台。它既有整理脚本的分镜头表，也有组织各步骤的项目画布。用户可以把脚本放进分镜头表，逐步整理镜头和提示词，再把相关内容送到图片生成等后续环节。

项目里的图片、提示词以及人物、场景、道具等素材可以集中管理和复用。视频环节提供的是提示词整理与向后续工具交接的能力，并不是按一下按钮就自动完成整部漫剧。我要接起来的，是客户原来需要在多个对话和工具之间反复复制、整理的那些步骤。

比如早期版本里的“720 空间场景”，我还专门整理了一张原理说明图：先生成一张全景母图，再在本地选择视角、输出画面。它不是可以自由移动的 3D 漫游。把这些能力和边界画清楚，也是在帮助双方确认，我们做的到底是什么。
