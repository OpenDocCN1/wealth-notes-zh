大家好，我是宋知远，加入生财不到一年。从 618 开始，这是我第三次参加 CPS 的 mini 航海。

这次航海，我最大的收获，是把自己反复做的剪辑工作，逐步整理成了一套可以批量运行、持续复用的流程。

我曾经是 2 年的剪辑师，CPS 一开始也是纯手搓：找参考、提文案、改密令、做配音、剪气口、加图片、调动画，再做封面。

每个步骤都会，但每多做一条，就得重新投入一遍时间。

这次航海刚开始的第一周，我基本没拿到什么佣金，视频数量也没有起色。由于主业工作太忙，经常需要加班，但能够投入到项目中的时间太少，我意识到，想增加产量，就得先解决制作环节对我的依赖。

于是，我给自己定了一个目标：

“不用我一直推进，这个工作流也能跑起来。”围绕这个目标，我开始用 Codex + Remotion 重做视频制作流程。日产出从原来的 1—2 条提升到 8 条，发布账号从 1 个增加到 5 个。最近 8 天，做出了 32 万 GMV、2300 元佣金。

这篇主要分享我怎么判断哪些环节适合交给 AI，以及怎么把自己的剪辑经验，变成它能执行的标准。

先说适合谁看：如果已经完整剪过 CPS 视频，知道一条成片应该是什么样，这套方法会更容易上手。如果第一天接触 CPS，我建议先亲手做完几条，建立基本判断，再逐步交给 AI。

因为你得先看得出问题，才能告诉 AI 怎么改。

### 一、为什么我选择 Codex + Remotion？

我目前做两种视频：一类是文字、图片、贴纸为主的 AE 风格动效漫播，另一类是真人口播。

这两类视频有一个共同点：文案和素材会变，但很多制作步骤是重复的。

比如，什么时候突出金额，什么时候放优惠图，密令出现时怎么强调，字幕怎样跟着音频走。这些判断一旦确定，就有机会沉淀成规则。

我也尝试过让 Codex 操作剪映，但在我的 Windows 使用环境里，有几个地方不太顺手：

- 1. 用 Windows 的时候 codex 老抢我鼠标去操控剪映，但我还有其他工作要做；通过界面识别、点击、等待完成剪辑，速度也没有达到我的预期。
- 2. AI+剪映的工作逻辑，更像每一步骤截图，然后让鼠标移过去，抠巴得很，remotion 的视频生成逻辑是写代码后渲染，天生更适合 AI 工作，更贴合我当前的视频类型：把文字、图片、动画和音频的关系写成代码，再渲染成视频。
- 3. codex 操控剪映只能一条一条剪，而且 computer use 太慢，但是 remotion 可以一次性 10 条视频一起渲染，具体看电脑配置

这样一来，很多要求就可以明确下来：

这句话出现时放哪张图，关键词在哪一帧进场，画面保留多久，下一组信息什么时候接上。

确定好的结构也能继续复用，批量安排制作和渲染。实际能同时跑多少条，要看电脑配置和视频复杂度。

我的选择依据，是这条制作链路能不能被清楚描述、稳定执行，并且减少我反复介入的次数。对我当前做的文字动效视频来说，Codex + Remotion 比较合适。

### 二、工作流怎么搭？先跑通一条，再逐步固定规则

我的整体流程可以用一条线概括：

参考视频 → 提取并核对文案 → 按账号修改指令和指定时间 → 生成配音 → 处理气口、建立字幕时间轴 → 配图和动效 → 制作封面 → 渲染检查 → 人工复核。

你的流程简单说就是：

找参考视频 → AI改成你的内容 → 自动做成片 → 你发布 → 看效果。

- 1. 找一条参考视频
  - 找同类带货攻略，把链接发给AI，告诉它用“我的口令”还是“??口令”。
- 2. AI整理文案
  - 结合原视频的声音和字幕提取内容，替换成你的口令，更新日期。先给你看，确认后再制作。
- 3. 准备画面和配音
  - 整理需要的商品图、优惠券图和文字动效，再生成配音，剪掉多余停顿，让字幕跟着声音走。
- 4. 自动做成视频
  - 加入图片、动态文字、背景音乐和重点提示音，再从内容里提炼封面文字，把封面放在视频开头。
- 5. 交付视频和标题
  - 检查口令、日期和字幕，成片自动保存到指定文件夹。一条视频配一条标题，方便直接发布。
- 6. 你发布，再看效果
  - 把视频发到对应账号，配好自己的推广口令。观察播放量、下单量和佣金，效果好的内容继续做。

你每次可以直接这样发：

> 参考这个视频，用我的口令，比例跟原片一样。日期改成×月×号，做出后把成片和标题一起给我。

你的主要工作就是：选参考、确认内容、发布和看数据。

#### 每个环节用什么

| 环节 | 用到的工具 | 简单理解它负责什么 | 提前配置什么 |
|---|---|---|---|
| 1. 接收任务 | Codex桌面端 | 接收链接或文案，安排后续的工作 | 登录账号，允许访问指定工作文件夹 |
| 2. 获取参考视频 | 浏览器+视频获取工具 | 打开参考链接，取得可分析的视频 | 工具可能需要登录；已有MP4可以跳过。这个环节受网站版权影响，不保证每条链接都能直接获取 |
| 3. 提取文案 | faster-whisper+OCR | 前者“听声音转文字”，后者“看画面识字幕”，两边交叉检查 | 本地语音识别模型、文字识别工具 |
| 4. 修改文案 | 文案Skill | 替换你的密令、更新日期，按要求保留结构 | 保存本人和群的口令表、日期规则、表达要求 |
| 5. 生成配音 | MiniMax API | 把确认后的文案读出来 | 开通账号、充值、配置API密钥和音色池 |
| 6. 剪气口、对字幕 | FFmpeg+时间戳脚本 | 剪掉多余停顿，再算每句话什么时候出现 | 本地处理脚本；这是字幕不跑偏的关键 |
| 7. 制作视频 | Remotion+视频Skill | 做文字动效、图片进出、口令展示，加入配音和音乐 | 安装Node.js和Remotion，准备模板、图片、BGM和提示音 |
| 8. 生成封面 | ImageGen | 从内容提炼三行重点，生成封面并放到第0帧 | 可用的生图能力，以及封面安全区规则 |
| 9. 导出与交付 | Remotion+FFmpeg；可选浏览器插件 | 输出MP4、飞传文件，发送视频和对应标题 | 输出路径；需要微信交付时，提前登录传输助手 |

这条流程看起来不复杂，实际跑起来，最花时间的是把每一步的交付标准说清楚。

我一开始也经历过：视频做出来了，但看着不对；提了修改意见，下条又出现相似问题。

后来我逐渐把反馈整理进 Skill。比如哪些文案不能动，密令要核对哪些位置，什么样的停顿需要剪，图片不能挡住哪里，封面怎么处理。

每解决一个反复出现的问题，就尽量把它变成下一次可以直接执行的规则。

其中，有三个环节最值得展开。

#### 第一个：文案先核对清楚，再让 AI 往下做。

我会把参考视频链接发给 Codex，让它获取视频、提取口播，同时对照画面字幕。

之所以做双重核对，是因为有些口播并不清晰。只依赖音频识别，容易出现漏字、错字，甚至把没听清的地方补成另一句话。

而 CPS 里，金额、时间、适用条件和密令，任何一处出错，都可能影响后面的转化。

所以，我的文案 Skill 有一个明确原则：默认保留原话术结构和优惠信息，只修改指定账号的密令，以及本次明确要求调整的时间。初期这样做，也方便控制变量。流程还没稳定时，同时大改文案、画面和音频，很难判断问题到底出在哪一环。

当然，这也意味着后面必须逐步建立自己的表达和画面，不能一直停留在参考复现阶段。这点后面再讲。

#### 第二个：音频先顺，画面再跟着音频走。

我用 MiniMax API 生成 AI 配音，主要考虑的是流程衔接。

文案确认后，可以直接生成音频，继续处理气口和时间轴，减少中间进软件、导出、再传文件的操作。

音色方面，我会先试听，挑出一批适合 CPS 的声音，再交给 Codex 调用。我的偏好是有精神、中气足、表达流畅，听起来愿意让人继续听下去。

成片里觉得不合适的声音，就从可用音色库里移除。

这里有一个很容易踩的坑：想让 AI 讲话连贯，不能直接把标点全部删掉。我现在会保留正常的逗号和句号，按完整语义断句，减少那些把一句话切得很碎的多余停顿。配音生成后，再处理过长的空白和可去掉的气口。

该停的地方仍然要停，数字和密令必须说完整。

另外，剪掉气口以后，字幕、图片和动画的时间也要跟着调整。否则音频已经往前走了，优惠图还停留在原来的时间点上。

所以，我会先把音频处理好，再让画面按新的时间轴对齐。

这也是我从手搓转向代码制作后感受很深的一点：以前觉得“这里快一点”就能表达的要求，现在需要进一步说明，到底是哪一段、快多少、会影响哪些后续画面。

#### 第三个：每做一条视频，都顺手积累下一条能用的素材。

我做 618 时已经攒过一批优惠图片，这次就让 Codex 优先从已有素材库里找。

库里没有的，再从参考视频中提取对应图片，检查图片内容、时间和入口信息，再决定怎么处理和使用。

这里尤其要注意图片里的密令：口播和字幕换好了，图片里还留着另一个账号的入口，整条视频仍然可能白做。

所以，检查范围不能只有文案，还要包括图片、封面和发布标题。

我给这一步定下的思路是：

先查库，缺什么再补什么，核对后归档，下次优先复用。

如果大家照着搭，建议同时保留素材来源和适用活动，后面更容易判断哪些还能继续使用。也可以逐步用官方或自有素材替换参考截图。

素材库积累起来以后，制作新视频时，就能减少大量临时找图的工作。

它会让下一条视频更容易做，这种积累值得一开始就设计进去。

### 三、两种视频，分别沉淀流程

动效漫播和真人口播，我会分开处理。

动效漫播的重点，是根据文案和音频组织文字、优惠图、贴纸、动画和音效。

真人口播则是先用同一套文案规则整理好话术，我拿去拍。拍完后，把素材交给Codex，处理气口、字幕和优惠信息图。

参考视频在这里主要帮助它理解：哪句话应该出现什么信息，图片放出来是为了解释什么。

两种视频的逻辑不同，我会用不同的对话和制作规则，减少混用。

封面也有区别：

动效视频可以单独设计封面；真人口播则尽量保留我的人脸，在首帧上补关键文字和图片。

为了减少发布时的操作，我会把封面嵌入视频首帧，并把重要信息放进居中的 3:4 区域。发布时再确认封面是否正确识别、文字是否被裁切。

说实话就是想偷懒想到的这招，这细节单独看都不大，但每天重复做，就会持续消耗时间。

### 四、从参考复现，到素材积累，再到自主改编

回头梳理，我觉得这条路可以分成三个阶段。每个阶段，先解决的问题不一样。

#### 第一阶段：借助参考，把完整链路跑通。

先弄明白一条视频从输入到输出，需要哪些步骤，每一步应该交付什么。

这一阶段，我会少改变量，优先解决文案错误、密令错误、音画不同步、信息看不清等基础问题。

进入下一阶段的信号，是：我发给 Codex 的指令，它能一次做对八成的步骤。

#### 第二阶段：把重复出现的东西沉淀下来。

反复要用的优惠图，进入素材库；反复提出的修改意见，进入 Skill；反复使用的画面结构，整理成可复用模块。

判断这一阶段有没有进展，可以看一件事：做下一条视频时，是不是少找了一次素材、少解释了一遍要求、少改了一类老问题。

我建议是每做完一批视频，回头看哪个环节修改次数最多，那个环节就是下一步要沉淀成 Skill 的。

#### 第三阶段：逐步增加自主改编。

当基础流程稳定、素材也有一定积累以后，就可以逐步调整文案表达、信息顺序和画面结构。

我原先也担心，文案不动、画面复现、图片还来自相似参考，会越来越同质化。

所以，这一步应该提前安排，不能等出现后台弹出‘审核提示’以后才开始想办法。

这里也不只是换个颜色、改个动画顺序。素材库和制作能力积累到一定程度，就应该开始尝试用自己的方式重新组织信息。

前面沉淀下来的流程，是为了给后面的内容尝试腾出时间。

### 五、数据是这套流程目前的一次验证

调整之后，我的日产出从原来的 1—2 条提升到 8 条，账号从 1 个增加到 5 个。

目前各账号平均每条视频千次播放，每天都有万播视频，隔天能出现单条 5 万以上播放的视频。最近 8 天，累计做到了 32 万 GMV、2300 元佣金。

对我来说，这次比较明确的变化是：

制作环节对我的占用减少了，我才有余力增加视频供给、配置更多账号，获得更多内容测试和反馈的机会。以前一天只能做一两条，就算是想多测，也很难腾出手。

现在产量上来以后，我可以继续观察哪些话术、画面和声音更适合，再把有效的经验补回流程里。

至于后续产量能做到多少，还要看选题、素材、审核和账号运营的承接能力。制作提效解决了一部分问题，后面的环节仍然要跟上。

### 六、“先完成再完美”，要落到发布动作上

我以前做过剪辑，很容易盯着细节一直改。

但 CPS 需要持续发布，才能拿到反馈。如果每一条都等到完全满意，产量就很难起来。

这次我给自己划了一条线：密令、时间、优惠信息要准确，声音听得清，关键内容看得见，音画没有明显错误。达到这些基础要求，就先发布。

动画还能不能更漂亮，转场还能不能更顺，可以继续优化，也可以改进到下一条里。

因为我觉得：

“好不容易做出来一条视频，10 个播放也是播放，万一就有人下单了。”这句话背后，是接受初期作品还不够成熟，让内容先进入真实反馈。

如果永远停在优化中，鸡蛋就永远变不成小鸡。

不过，发布以后也要把问题带回来。哪类反馈值得处理，哪些错误再次出现，就继续修改流程。这样，“先完成”才会逐渐走向“做得更好”。

### 七、我目前跑通了什么，接下来准备验证什么

目前，这套方法主要用在我的 AE 风格动效漫播和真人口播剪辑里。其他类型的视频，我还没有充分验证。

我觉得可以继续往外尝试的方向，是那些结构比较固定、文字和图片占比高、需要持续换内容的视频。

AI 接手了很多执行工作，我也在学习怎样把自己的判断交代清楚。

这次航行的结果，给了我继续完善这套流程的动力。

接下来，我更想验证的是：当素材库更完整、规则更稳定以后，能不能进一步减少返工，把更多时间放到选题、内容差异化和账号运营上。
