### 3. 知识资产工程化：从直播逐字稿到赛道专属 Agent 的 Harness 知识图谱

很多创作者最大的困惑是：**为什么我听了十几场大咖直播、买了几十节课程，轮到自己动手时依然一脸懵，或者一发文就踩坑？** 因为直播和课程是典型的“流式信息”：

- 一场两小时的直播答疑，录音转写出的文字往往多达 **2~3 万字**；
- 里面充斥着大量的口语停顿（“嗯、啊、对吧”）、闲聊客套、学员打断提问、碎片化的单点案例；
- 如果你试图把几万字逐字稿直接扔给通用大模型，大模型要么因为上下文太长而严重遗忘，要么被水话带偏，总结出一堆“看似有道理、实则毫无实操意义”的泛泛公文包。

更致命的是，**如果没有把自己的事实、案例和边界交代清楚，AI 更容易给出泛泛的回答。** 知识库能补上下文，但也要检查资料来源与更新日期。

## (1) 第一步：调用「逐字稿精读笔记 Skill 」，对两万字长文本三层脱水

面对教练动轴两三万字的直播转写稿，我们直接调用本地配置的逐字稿精读笔记 Skill（progressive-transcript-notes）。该 Skill 严格遵循“渐进精读法”，按三层递进整理长文；耗时取决于篇幅、模型与人工核对：

- Layer 1（全局脉络骨架）：第一层用 500 字直接提炼该场直播的核心论点与推导脉络，快速锁定整场分享的底层逻辑；
- Layer 2（因果推理链与边界反例还原）：这是最值钱的一步！普通总结只会留下“要做 A”，而渐进精读 Skill 会极其严格地保留讲者“为什么做 A”的完整论证链条、真实学员正反案例，以及最重要的【适用边界与反例】。

*例如：在分析生活奇闻赛道时，Skill 不仅记录要打视觉反差，更完整记录了教练强调的反例——“绝对不能做苦难压抑叙事与沉重说教，因为读者点开贴图号是为了解压、猎奇与社交谈资，沉重叙事只会招致反感甚至举报”。*

- Layer 3（实操参数与金句卡片）：精准抓取带有明确约束的业务参数（如正文建议字数、首图 3:4 比例、文案大字报字幅控制在 40%、日发布间隔 2 小时等），并单独归纳教练的金句。最终输出一份忠于原文、毫无废话、可直接检索的 Markdown 精读笔记。

## (2) 第二步：调用「方法论提炼与执行化 Skill」，把经验转化为 AI 能执行的 SOP

精读笔记虽然清晰，但它依然是“写给人看的教程”，而 AI 写稿需要的是“指令级 SOP”。怎么把人的经验整理成 AI 容易执行、也便于人检查的规则？

我们调用 方法论提炼与执行化 Skill（methodology-distiller）进行二次工程化提纯：

- 经验单元切片：抽出标准的五元结构：面临痛点 → 讲者判断 → 采取动作 → 核心参数 → 验收标准；
- 逻辑分支化（IF-THEN 决策树）：将教练口头零碎的答疑整理为判定条件。例如：
- IF 选题属于民间奇闻 THEN 首图采用脏旧废弃环境 + 高价值物品强烈反差，正文必须注入真实考古/民俗知识增量，文末平实总结；
