## **Obsidian**是什么

它既是Markdown编辑器也是知识库应用，笔记以本地纯文本文件保存，可以编辑、搜索和浏览文档，也可以通过链接连接不同笔记，强调数据可持久访问和避免平台锁定。

## 设置本地文件夹路径

在电脑上创建一个空文件夹，建议根目录用英文，内部目录用中文。这样做的好处是：

- 英文路径兼容性更好。
- 中文目录方便自己理解。
- 以后迁移、备份、让AI读取时更稳定。

打开Obsidian，选择刚创建的KnowledgeBase文件夹。

如果打开Obsidian不是打开本地仓库的页面，而是以前建过本地仓库了，可以点击底部仓库路径选择管理仓库，重新创建一个新的。

## 使用路线

### 本次知识库简介

最小闭环版-个人AI知识库由四层组成：

1. **本地资料**：Markdown、PDF、附件等真实文件。
2. **结构说明**：README.md告诉人和AI每个目录怎么使用。
3. **操作规则**：AGENTS.md规定哪些事可以直接做，哪些必须确认。
4. **AI协作**：Codex负责检查、提方案、执行已确认的操作并自检，用户保留最终判断权。

Skills和总控Agent属于成熟阶段的自动化能力，不是第一次搭建的必要条件；等真实流程稳定重复后再增加。

7. 自检完成后，再统一汇报实际创建结果。

# 放入 3 份资料并完成第一次整理

如果没有自己可以测试的本地文件，使用以下 3 份文件即可：

由用户把 3 份可以公开或可以安全测试的资料副本放入：

00\_收集箱

不要使用唯一一份重要资料，也不要一次导入全部历史文件。

然后发送：

请先读取当前知识库的 README.md 和 AGENTS.md，再检查 00\_收集箱中的 3 份测试资料。请用表格列出：
- 文件名
- 建议位置
- 分类理由
- 目标位置是否已有同名文件
- 是否需要我确认

现在只输出整理方案，不移动、删除、重命名或修改文件。如果现有目录已经能承接资料，不新增分类。原始资料默认保护正文，不要用总结替换原文。如果你需要我确认分类选项，我的回答只用于确定整理方案，不代表授权执行；在我发送下一条执行提示词前，不要操作文件。

不满意就直接告诉 Codex 修改意见。

确认方案后发送下面的提示词：

我确认刚才的整理方案，请只处理这 3 份测试资料。执行前检查目标路径和同名文件，不覆盖、不自动合并，不删除文件，不改写原文。整理完成后检查文件数量、目标位置和原位置，再汇报实际结果。

# 基于资料完成一次真实任务

选择一个现场可以完成的问题或输出：

如果你使用的是本次文档中给3份测试文件，可以复制上面这段任务描述指令来进行测试。

请阅读刚才整理的 3 份资料，完成下面的真实任务：【填写问题或需要输出的内容】要求：
1. 只依据当前资料和可以明确识别的事实回答。
2. 列出参考文件名或相对路径。
3. 区分资料中的信息、你的归纳结论和 AI 推断。
4. 资料不足时明确告诉我缺少什么，不要补写不存在的事实。
5. 先在对话中输出，不要直接写入知识库。

如果结果符合需要，可以再说：

【要输入具体的目录，没有目标目录可以输入“帮我创建用于XX的目录，目录结构根据你的建议来”。】

第一次闭环包括：

资料进入→ Codex 提出整理方案→ 用户确认→ 文件完成整理→ 基于资料完成真实任务→ 结果继续沉淀回知识库

1. 我想解决什么问题。

# 从第一次操作进入日常使用

完成现场这组操作后，知识库才开始进入日常使用。我后来最常用的四类任务，都来自下面这些可以直接说给 Codex 听的话。

## 第二部分：日常使用｜四句话管理知识库

日常只需说清任务、资料范围和确认边界；AGENTS.md 与已经验证的流程负责其余约束。

**1. 帮我整理知识库／帮我整理新增资料**

帮我整理新增资料。先检查并给出方案；涉及新增分类、移动、重命名、覆盖或修改原文时，等我确认后再执行。

**2. 帮我创建项目**

帮我为【项目名称】创建项目。先检查是否已有同名或用途重叠的项目，再给出项目目录、目标、交付物和 PROGRESS.md 方案。等我确认后创建。

**3. 帮我检查哪些文档需要更新**

请只读检查当前知识库中哪些文档需要更新。重点检查 README.md、AGENTS.md、已有文件目录.md、相关项目 PROGRESS.md，以及内容与实际状态不一致的文档。先列出理由和修改建议，不要直接修改。

**4. 帮我基于 XX 资料输出 XX 内容**

请阅读【资料范围】，基于这些资料输出【目标内容】。列出参考文件名或相对路径，区分资料内容、归纳结论和 AI 推断。资料不足时告诉我缺少什么，不要补写不存在的事实。先在对话中输出，等我确认后再保存。

### 更多常用说法

| 场景 | 可以直接说 |
|------|-----------|
| 规整格式 | 帮我规整这些文档的格式，不要改动原文内容 |
| 整理剪藏 | 整理网页剪藏入口中的文章，分类不确定时先告诉我 |
| 继续项目 | 先读取项目 PROGRESS.md，再继续推进，完成后更新进度 |
| 学习评估 | 阅读相关资料，总结当前掌握程度和下一阶段行动建议 |
| 知识问答 | 根据指定资料回答问题，列出参考文件，资料不足时明确说明 |
| 执行方案 | 可以，按刚才确认的方案执行，完成后自检 |

# 第三部分：进阶选学

等真实需要出现以后再扩展

日常任务用过一段时间以后，再处理备份、项目和 Skills。下面的内容可以按需要选择，不用在第一次搭建时全部完成。

## 完善个人知识库

### 隐私与数据边界

“本地知识库”表示原始文件保存在自己的电脑上，不代表 AI 处理过程完全离线。Codex 读取资料并回答时，相关内容仍受当前账户、套餐、数据控制和组织规则影响。

开始前需要注意：

- 检查 ChatGPT 的数据控制设置和组织管理要求。
- 不在知识库中保存密码、API Key、验证码、恢复码等访问凭据。
- 身份证件、财务、医疗、合同和客户资料只提供完成任务所必需的最小范围。
- 对外分享或生成平台副本前再次检查隐私。

### 生成更完整的个性化方案

现场已经跑通最小闭环的人，可以继续补充真实需求：

请只读检查当前知识库，不要修改文件。请先向我了解：
1. 我建立知识库的长期目标，以及希望得到哪些输出。
2. 我经常保存哪些资料，资料来自哪里。
3. 我已有的文件、目录和正在推进的项目。
4. 我对目录命名、分类数量、操作确认、隐私保护和 AI 协作方式的偏好。

然后结合当前实际文件，输出一份完整修订方案，包括：
- 推荐目录和每个目录的必要性
- 资料进入、整理、使用、产出和归档的流向
- README.md 和 AGENTS.md 的调整建议
- 是否确实需要文件目录.md
- 只有存在长期项目时才考虑项目 PROGRESS.md
- 现有资料迁入方式
- 日常管理方式
- 执行顺序、确认节点和验收标准

目录先少后多，不要为了完整而创建暂时没有真实用途的分类。现在只输出方案，不操作文件。

Codex 输出方案后，用户需要确认：

- 目录名称是否容易理解。
- 分类之间是否存在重叠。
- 每个目录是否有真实资料来源或真实用途。
- 文件移动、原文保护、备份和隐私边界是否能够接受。
- 执行顺序和完成标准是否清楚。

### 什么时候需要文件目录.md

文件目录.md 不是第一次搭建的必做文件。

满足以下情况之一时，可以让 Codex 根据实际文件生成：

- 文件数量已经明显增加。
- 资料分散在多级目录中，经常找不到位置。
- 需要一张可以快速搜索文件名、类型和路径的索引。
- 需要检查资料是否已经归档或是否存在重复文件。

请只读扫描当前知识库的实际文件，根据真实文件生成文件目录.md。至少包含：
- 文件名
- 资料类型
- 当前目录
- 相对路径
- 更新时间

要求：
1. 实际文件系统是唯一事实来源。
2. 文件目录.md 只是可以重新生成的索引。
3. 不根据旧索引移动文件。
4. 不记录对外分享时不应公开的完整本地路径。
5. 现在只创建或重建索引，不移动、删除或修改资料正文。

如果索引和实际文件不一致，应重新扫描实际文件，而不是按照旧索引调整文件。

### 备份和高风险操作

第一次低风险测试使用资料副本。

以下操作开始前必须建立知识库外的可恢复副本：

- 批量移动或重命名。
- 删除或覆盖文件。
- 目录重构。
- 大规模正文修改。
- 导入大量唯一原件。

备份完成后至少核对文件数量，并随机打开重要文档或附件。同步盘主要解决同步，不应作为唯一备份。

### 格式规整与原文保护

Codex 默认可以直接处理：

- 多余空行和纯空格行。
- 行尾空格和不可见字符。
- 导入造成的重复首标题。
- 空标题。
- 明显断裂的数字序号和项目符号。
- 列表项之间不必要的空行。

Codex 默认不能直接处理：

- 改写或润色正文。
- 删除看起来重复但可能有意义的段落。
- 调整观点顺序。
- 改变标题层级所表达的含义。
- 用摘要替换原文。

如果分不清是格式修复还是内容修改，一律先询问用户。

### 完整基础验收

现场 4 项完成清单通过后，可以在课后进行更完整的检查：

- Obsidian 能正常打开知识库。
- Codex 已只读验证知识库路径和实际文件。
- 目录来自自己的真实目标或明确选择的最小方案。
- README.md 与实际目录和资料流向一致。
- AGENTS.md 保持精简，并包含确认、原文保护、同名检查和自检规则。
- 如果创建了文件目录.md，它与实际文件一致并可重新生成。
- 高风险操作前有知识库外的可恢复备份。
- 敏感信息检查不会复述具体值。
- 第一批资料完成了先方案、确认后执行。
- 同名文件没有被自动覆盖或合并。
- 格式规整没有改写原文。
- 已经完成一次带来源的真实问答或内容输出。
- 需要长期推进的项目有 PROGRESS.md。

请只读检查当前知识库是否完成从 0 到 1 的基础搭建。请用表格输出：
- 检查项
- 状态
- 实际证据
- 需要修正的内容

只检查当前实际存在的基础功能，不要把网页剪藏、项目管理、第三方平台、Skills 和总控流程作为通过条件。现在只检查，不修改文件。

### 建立项目管理

满足以下任一情况，就适合建立项目：

- 有明确目标和交付物。
- 需要跨多次对话推进。
- 有重要决策和下一步需要记录。
- 相关资料会持续增加。

请在知识库中为【项目名称】建立项目目录和 PROGRESS.md。PROGRESS.md 包括：
- 项目目标
- 当前状态
- 已完成
- 最近决策
- 下一步
- 待确认问题

要求：
1. 先检查是否已有同名或用途重叠的项目。
2. 如果存在重叠，只汇报现状、差异和建议，等我确认后再创建。
3. 不要编造已经完成的事项。
4. 创建完成后检查 README.md 是否需要更新。
5. 如果已经使用文件目录.md，再根据实际文件更新索引。
6. 最后检查项目目录、PROGRESS.md 和相关说明是否一致。

以后继续项目时可以说：

请先读取【项目路径】中的 PROGRESS.md，再继续推进【本次任务】。完成后更新项目进度并自检。

## Skills 和总控流程

### Skills 从重复任务里来

我的 4 个 Skills 也是在知识库已经投入使用以后才做的。先让真实任务重复出现，再把稳定步骤写成 Skill，会更容易判断它负责什么，也更容易检查执行结果。

先理解三个概念：

| 名称 | 普通理解 | 例子 |
|------|---------|------|
| AGENTS.md | 整个知识库长期遵守的精简规则 | 不擅自删除文件、保护原文 |
| Skill | 一项重复工作的固定步骤 | 资料分类、格式规整、项目进度更新 |
| 总控流程 | 根据任务选择和组合合适的 Skills | 收到整理任务后依次分类、规整和自检 |

Skill 是 Codex 可以识别的可复用工作流。

项目级 Skill 放在：

.agents/skills/【Skill 名称】/SKILL.md

每个 SKILL.md 至少需要包含 name 和 description，并且只负责一类明确任务。

本手册中的：

.agents/knowledgebase-manager-agent.md

是作者使用的本地总控流程文件，不是平台自动注册、也不是后台独立运行的 Agent。它需要用户发起任务，并由 AGENTS.md 指示 Codex 读取后才会工作。

### 什么时候创建

先正常使用知识库。当一项操作重复出现 3 次以上，而且步骤和判断基本稳定时，再考虑做成 Skill。

请读取当前知识库的 AGENTS.md、README.md、已有项目 PROGRESS.md，以及当前能够看到的知识库管理记录。找出有证据表明重复出现 3 次以上、步骤和判断已经比较稳定的操作。请输出一份完整的 Skills 和总控流程方案，包括：
1. 哪些操作适合做成 Skill，并列出重复出现的证据。
2. 哪些操作证据不足，暂时不应做成 Skill。
3. 每个候选 Skill：
   - 负责什么
   - 不负责什么
   - 在什么情况下触发
   - 建议名称
   - 建议保存路径
   - SKILL.md 中的 name 和 description
   - 核心执行步骤和安全边界
4. 哪些 Skills 可以由一个总控流程组合调用。
5. 是否需要创建总控流程文件，以及建议保存路径。
6. 根目录 AGENTS.md 需要增加或调整的路由规则。
7. 计划创建和修改的完整文件清单。
8. 创建后的低风险测试方法和验收标准。

项目级 Skill 默认规划到：

.agents/skills/【Skill 名称】/SKILL.md

总控流程如果确实需要，默认规划到：

.agents/knowledgebase-manager-agent.md

以上路径和结构也必须作为方案的一部分供我确认。证据不足时明确标记“证据不足”，不要自行假设。现在只输出完整方案，不创建或修改文件，等待我确认。

### 确认后创建

我确认使用刚才最终确认的 Skills 和总控流程方案，请按照确认内容执行。执行前：
1. 检查计划中的目标目录和文件是否已经存在。
2. 如果存在同名 Skill、总控流程或 AGENTS.md 路由冲突，立即停止并报告差异，不要覆盖或自动合并。
3. 再次核对准备创建和修改的文件是否都已在确认方案中展示。

确认没有冲突后：
1. 只创建确认方案中选定的 Skills。
2. 按照确认方案中的名称、路径、name、description、职责、触发条件和安全边界写入 SKILL.md。
3. 只在确认方案需要时创建总控流程文件。
4. 只按照确认方案修改根目录 AGENTS.md 中的启动和路由规则，不复制全部 Skill 细节。
5. 不自行增加、删除或合并未经确认的 Skills。
6. 未经授权且没有固定规则覆盖时，删除、移动、重命名、目录调整和正文修改仍然必须先确认。
7. 创建完成后只检查：
   - 文件路径和名称
   - YAML 元数据
   - Skill 职责与触发条件
   - 总控流程引用
   - AGENTS.md 路由
8. 本次不要自动运行真实知识库整理任务。

完成后告诉我实际创建和修改了哪些文件、自检结果，以及应该使用什么低风险任务进行第一次测试。

第一次测试使用少量资料，并明确说：

请使用 knowledgebase-manager-agent 帮我整理新增资料。先检查并给方案，不要直接执行高风险操作。

如果 Skill 没有出现在 Codex 中，先检查路径和 SKILL.md 元数据，再刷新或重启 Codex。

## 附录C：对外分享和隐私保护

对外分享时只分享系统，不复制自己的完整知识库。

必须排除：

- 姓名、账号、联系方式、真实路径和访问凭据。

请生成这套知识库的对外分享版本。只保留通用目录、规则、Skills、总控流程、空白模板和虚构示例。排除个人资料、私人项目、历史对话、原始资料、剪藏正文、附件、真实路径、账号和访问凭据。先输出保留清单和隐私排除清单，等我确认后再生成。生成后检查最终发布文件夹或ZIP，而不只是检查源目录。疑似敏感信息只报告文件路径和信息类型，不展示具体值。输出隐私检查报告，并提醒我进行人工最终复核；不要自行宣布"可以直接发布"。
